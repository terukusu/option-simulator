# UI / UX 再設計（設計書）

option-simulator の画面を「書類」から「計器」に作り直すための設計書。計算（`model/`）・表示モデル（`ui/view/`）・状態と保存（`ui/state.ts`・`ui/persist.ts`・`ui/share.ts`・`ui/book.ts`）はそのまま使い、作り直すのは **見せ方と触り方の層**（`ui/components/`・`ui/style.css`・`ui/chart/` の一部。旧の部品・旧 CSS は #91 で削除）だけ。今ある機能はすべて残す（置き場所と出し方を変える）。

触れる試作品は [`ui-redesign/prototype.html`](ui-redesign/prototype.html)（単体の HTML。値はすべて架空）。撮影した画面は同じフォルダの `proto-*.png`。

- 読む人: オーナー（採否の判断）と実装者（Issue に分ける人）
- 数値・銘柄の例はすべて **架空の値**
- 用語: 「板」= 気配の一覧、「足」= ポジションの 1 本、「シナリオ点」= X₀ + ΔX、「BOX タブ」= 作業中のポジションのタブ

---

## 1. 設計の原則（このツールならではの芯）

オーナーの主な使い方は「シナリオ（経過日数・原資産・IV）を動かして **期中の損益** がどう変わるかを見る → 流れでポジションを少し直す」。だから画面の芯は次の 5 つにする。

| # | 原則 | 具体 |
|---|---|---|
| 1 | **損益の面を手で撫でる** | 損益グラフが舞台。シナリオの 3 軸（ΔX・d・Δσ）は欄に打つものではなく、グラフの **横（X）・下の帯（時間）・右の帯（IV）** を直接つかんで動かす。読み取りの数字はつかんだ瞬間に追従する |
| 2 | **常に見せる数字は少なく、大きく** | 画面に固定で出すのは「指定日の損益」「満期の損益」「Δ」の 3 つ（PC は Θ・V・受取も）。他はパネルを開く。文章で状態を説明しない（印・色・トースト） |
| 3 | **触る頻度で置き場所を決める** | 毎回触る（シナリオ・足の枚数・板の bid/ask）は手前、ときどき触る（プリセット・評価時刻・ヘッジ・ピン）は 1 タップ、ほぼ触らない（ATM 基準・単位・手数料・証拠金・テクニカル指標の期間）は設定へ。同じ機能への入口は 1 つ（#275: β・sticky・basis・ΔX の単位はシナリオの「モデルの前提」、縦軸は舞台の ⋯、テーマは ☾（スマホは設定）） |
| 4 | **画面は 1 枚の長い紙ではなく、固定の舞台と引き出し** | ページはスクロールしない。スクロールするのはパネルの中だけ。スマホは上に舞台・下に引き出し（親指の届く位置に操作）。PC は 3 面（市場・舞台・作業台） |
| 5 | **因果が追える動き** | 離散の操作（プリセット・枚数 ±・タブ切替・足の追加）は線が 200ms で補間して動き、連続の操作（ドラッグ）は即時。追加・削除は「元に戻す」付きのトーストで知らせる |

「静かで精密」な見た目: 面は暗い無彩色、色は意味のある所（損益の符号・シナリオ線・つかむ所・bid/ask）にだけ使う。数字は等幅・タブ付き数字で桁が揺れない。

## 2. 画面の骨組み

幅で 3 段階。境は今と同じ（`PHONE_QUERY` = 719.98px、PC = 1200px）。どの段階でも **ページ全体はスクロールしない**（`body { overflow: hidden }`、高さ `100dvh`）。

- 板の表は 5 列（K・bid・ask・IV b/a・Δ）、put / call はセグメントで切替

### 2.3 タブレット（720〜1199px、例 900×1100）

```
┌───────────────────────┬──────────────────┐
```

- 2 列。左 = 舞台 + シナリオ（常設なのでドックに「シナリオ」は無い）、右 = ドックで切り替える 1 枚（ポジション / 板 / 指標 / IV = IV 推移・スマイル）

- 列の比: 市場 `minmax(340px, 30%)` / 舞台 `1fr` / 作業台 `minmax(360px, min(28%, 420px))`。1280 で舞台 ≈ 540px、1440 で ≈ 600px、1800 で ≈ 760px
- 板の列数は **板の枠の幅** で決める（≥ 540px で 9 列、≥ 410px で 7 列 = Δ 無し、未満は 5 列 + put/call セグメント）。1800px 以上で 9 列になる。枠の幅は `section.board` の幅（枠線を含む。1800×1000 で 540px、1440×900 で 432px、1280×800 で 384px）で測る（`.panel-body` の `clientWidth` は枠線の 1px を除くので 1800 で 539px になり 9 列にならない。#85）。実機の等幅（Menlo / SF Mono、半角 0.6em）で 322 行の板の最小幅は 9 列 475px・7 列 403px（§5 の `table.board` の詰め方 + バッジを K の数字の下に積む）。試作品の CSS（セルの左右 5px・ボタン 8px・バッジを K の左右）では 9 列 585px・7 列 502px が要り入らない
- 舞台・シナリオはコンテナクエリで自分の幅に合わせる（読み取りの個数・ステッパーの列数・拡大ボタンの表示）。読み取りは舞台の幅 ≥ 600px で 6 つ（480〜599px は 5 つ、< 480px は 3 つ）。シナリオのステッパーは幅 ≥ 600px で 1 行 4 列（1440 のシナリオ ≈ 605px。4 列では ± を 24px に詰め、値の欄 ≈ 83px に最長の「−27,100 円」≈ 71px が入る）、未満は 2 行 2 列（#83）
- ドックは無い。板 / スマイル / IV 推移（#79）/ 先物推移（#190）は市場列のセグメント `[板 | スマイル | IV 推移 | 先物]` で切替。各列は独立にスクロール
- AI のチャット（#135）は作業台の列（ポジション + 指標の 2 段）を一時的に入れ替える（`ShellState.bench` = `work` / `ai`。保存しない）。トップバーの [AI]（押されている間は強調）・キー 6 で入れ替え、キー 3 / 5（#275 の並び）・舞台の足マーカーのタップでポジション・指標に戻る。舞台・市場の列はそのまま

## 3. 情報の階層

「常に見せる」= 画面に固定で出す。「触ったら出す」= 1 タップ（パネル・ポップオーバー・メニュー）。「奥にしまう」= 設定・⋯・ヘルプ。

### 4.1 損益グラフ（舞台の描画域）

- 長押し中は文字選択・コンテキストメニューを出さない（今と同じ）
- 十字線はどのチャートもタップで置く（#217。下の「十字線の共通の規則」）。長押しは損益グラフではシナリオ点・足マーカーのまま
- ドラッグ中は線の補間（§7）を切り、離したら戻す
- ΔX の範囲・刻み（10 円格子、−90%〜+100%。#144 で広げた）・d の範囲（0〜最遠の SQ）・Δσ（−10〜+40pt、0.5）は今のまま

**新しい画面（#82）の決め**（旧画面は今のまま）:

- ハンドルは ΔX = 0 でも X₀ の上にある。つかむ幅は ±14px（旧画面は ±12px のまま。`gesture.ts` の `GestureCtx.scrub.grabPx`、省略時は今の `GRAB_PX`）
- キー: ← → は ΔX（旧画面の `, .` `< >` と同じ刻み・範囲。← → でパンはしない）、↑ ↓ は Δσ ±0.5pt（`sliderSpec('dSigma')` の格子）、`[` `]` は d ±1 日（格子に乗せない。目盛りのタップで入った端数を保つ）、0 はシナリオを 0 に、+ − R は今のまま。解釈は `ui/view/stage.ts` の `stageKey`
- 操作の優先: (1) 足マーカーの当たり判定（横 ±8px・横軸の上 14px の帯）→ タップで足を選ぶ、長押し 450ms → 横に滑らせて行使価格を変える（板の OP の足だけ）、長押し前に 6px 動けばパン (1') タッチで置いた十字線の交点 ±14px（距離。#201）→ 十字線を即つかむ (2) ハンドル ±14px → ΔX を即つかむ（動かさずに 450ms 未満で離せばタップ = 十字線） (3) それ以外 → パン / 長押しで ΔX / タップで十字線。マーカーのタップはダブルタップ（リセット）の 1 回目に数えない（マウスの dblclick もマーカーの上では無視）。マーカーのドラッグ中に 2 本目の指が来たら取り消す（確定しない）
- シートを全開にした舞台（92px）の描画域はミニ（線・塗り・0 の線・ハンドルの縦線だけ）で、操作を受けない
- IV レールの感度は 0.25pt / px まで。レールが短い（トラック < 200px）ときは押した位置に飛ばさず、縦の移動量で動かす（相対）
- 時間レールの現在値の吹き出しはつまみの下の文字の行に置き（描画域の目盛りの文字を隠さない）、重なる目盛りの文字は出さない
- 凡例行のピン（①②③ + 名前 + ×）は線の凡例より先に場所を取り、縮むのは名前だけ（名前は省略記号。× は 24px の当たりで常に押せ、右のツール（ピン・拡大縮小・⋯・ⓘ）は縮まない。ピンのメニューにも「① 名前 を外す」）。交点のラベルは線（満期・指定日・今日。線とは縦に 3px 空ける。#279）・他のラベル・IV レールの吹き出しに重ならない位置へ上下にずらす（元の位置から ±45px に無ければ縦線の反対側、それでも無ければ描画域の高さまで広げる。`stageMarkLabels`）

**十字線（#201）の決め**:

- 用途: 任意の X の 3 本の損益と、ある損益の水準を読む（オーナーの要望 2026-10-20: 最大損失を −1,000 千円で止める put の行使価格を探す）。シナリオは変えない読み取り専用の表示。規則は `ui/view/pnlCrosshair.ts`（純関数）、決定の詳細は docs/design.md 13.4「損益グラフの十字線」
- 見た目: 縦線 = X（10 円の格子）、横線 = カーソルの高さ（線に吸着しない。§4.7 の #130 と同じ）。線は `--ink-2` の破線（X₀ の点線 `--ink-3` と区別）。横軸の札 = X・縦軸の札 = 横線の高さの損益を IV 推移と同じ札（矩形 `--ink-2`・文字 `--s1`・等幅 `--fs-xs`・高さ 15px）で目盛りの上に重ね、svg の内側へ寄せる。線の上の点（白抜き・線の色）。読み取り = `満 / 指 / 今` + 符号つきの金額 + 単位（**グラフの縦軸の単位**）を積み上げた箱（11px・縁取り `--s1`・線の色。交点のラベルと同じ）を縦線と反対の側の上端に、箱が縦線の上の点を覆うなら下端（足マーカーの帯の上）に、障害物（IV レールの吹き出し・追証の札・交点のラベル）を避けて置く。360px の描画域（約 230px）に 1 行の横並びは入らないので積み上げ
- PC: ホバーで出る（ボタンを押していない間）。ドラッグ（パン）・ハンドル・長押しは今のまま。**シナリオ点・足マーカーをつかんで動かす間（ハンドルの即つかみ・長押し）は十字線を出さない**（#223。離してマウスを動かすとまた出る）。パンで押している間は十字線が値の座標のまま（パンで付いて動く）。クリックでは置かない
- タッチ: 長押しはシナリオ点のつかみ（#52）のまま、空いている **タップ** で置く（#217 で全部のチャートがこの形にそろった）。置いた十字線は交点の ±14px を押すとすぐつかみ（`gesture.ts` の `cross`）、ドラッグで動く（パン・長押しを待たない）。出ている間のほかの所のタップ（描画域の中・外・読み取りの箱・×）・ダブルタップ（リセット）で消える（#217 で「箱のほかの所のタップは移す」をやめた = 移さない）。パン・ピンチ・長押しでは消えない（値の座標に残る）
- ミニ・空の舞台は十字線なし。面モードは #217 で PC のホバーだけ足した（タッチは押すとすぐ点をつかむので空いている操作が無く、読み取りは点のラベル）。線と面を切り替えたら消す
- 検査: `npm run ui:check` の既定に 360 / 1440 × ダーク / ライトのホバー 4 か所（線 2 本・札 2 個が svg の内側・文字が札に収まる・読み取りが描画域の内側・札 = 目盛りの値・縦 / 横スクロールと折り返し 0）、`--flows` に 1440 のホバー（縦線 = マウスの X・横線 = マウスの高さ・外れて 0・パン・長押し）と 390 のタッチ（タップ・交点のドラッグ・読み取りの箱のタップで消える（#217）・× のタップ・長押し・パン・描画域の外のタップ）

**十字線の共通の規則（#217。すべてのチャート）**: オーナーの指示（2026-10-20）「付けられるところは付けといて。操作に一貫性は大事。」と、タッチの操作のオーナーの案（2026-10-21）「タップで出す／消す、次のタッチが中心付近だと掴めて動かせる、別の場所をタップで消える」で、十字線のあるチャートはこの規則にそろえる。ねらいは、段・ミニのチャート・損益グラフのほかの操作（長押し・ダブルタップ・パン）とぶつからないこと。チャートごとの値の決め（読み取り・札の桁）は各節と docs/design.md 13.4「十字線の共通の規則」

### 5.1 折り返しの規則

1. **数値・ラベル付きの値・ボタンの文字・セグメント・チップは折り返さない**（`white-space: nowrap`）。入らないときは (a) 省略記号、(b) 副題を隠す、(c) ⋯ メニューへ退避、の順で対応する。(a) 省略記号 — 指標のタイル・舞台の読み取りの副題は全文をポップオーバーで読める（#107。副題の文は 360px の 2 列に収まる長さに整理し、省いた項目は全文に出す）
2. 折り返してよいのは **説明文**（ⓘ の中・テール表の注記・空の状態の案内）だけ
3. 行の中で要素が入らないときは行を折らず、**横スクロール**（チップ行）か **列数の変更**（板・ステッパー）で対応する
   - 例外: AI の定型の質問の行は折り返す（#277。チップは 6〜7 個で全部を見せる。チップの文字は 1 の規則どおり折らない）
4. 幅 360px でも横スクロールが出ないことを維持（試作品は 390 で `scrollWidth = 394`。4px は丸めの誤差で、実装では 0 にする）

**面モード（#88 段 A）の決め**（表示モデルは `ui/view/pnlSurface.ts`、描画は `ui/next/stage/SurfaceCanvas.tsx`）:

- 格子: 横 = 線と同じ表示範囲（`pnlViewDomain`）、縦 = d の 0（下 = 今日）〜 最遠の SQ（上 = `maxDays`）。値はセルの中心で `theoreticalPnl`（指定日の線と同じ式。新しい計算は無い）
- 色: 符号で `--gain` / `--loss`、不透明度 `210 × (|v| / vmax)^0.6`（vmax = 格子の有限の |v| の最大。0 で透明 = 決定 2。試作品の下限 20/255 は採らない）。vmax < 1 円・非有限のセルは透明
- 描くもの: 格子線・目盛り（縦は整数の日、左上に「日」。「日」と重ならないよう、0 以外で上端から 12px 未満の目盛りは出さない）・X₀・シナリオ ATM・追証の線（#131）・足マーカー・シナリオ点（縦線 + d の横線 + ● + 輪 + ラベル「{金額}{単位} · d {d}」）・▼ のつまみ。描かないもの: 線・塗り・0 の線・BEP・ピンの線とラベル・交点
- 点のラベルは点の右上、描画域・IV レールの吹き出しにかかるなら 左上 → 右下 → 左下 の順に替える
- ±vmax と濃さの正規化は描いている格子の最大（粗い格子の間は粗い格子の最大、止まると細かい格子の値。両者は少し違ってよい）
- 足 0 本・評価できる足が無い（`model.empty`）ときは面モードでも凡例行・ⓘ・⋯ を線モードの空の表示にする（`[線 | 面]` の押された状態は保つ）
- 凡例行: 線の凡例の代わりに色の見本（`--loss` → `--s1` → `--gain`）+「損益の面（横 原資産 · 縦 経過日数）±{vmax}」（舞台の幅 < 480px は「損益の面 ±{vmax}」、vmax は指標の単位）。「指定日 d を最遠の SQ に収めた」のタグは出す。ピンのチップ・「プレミアム 0 のため自動」のタグは出さず、⋯ の縦軸の欄は「縦軸は経過日数（面モード）」の注記に替える（ピンの状態・[ピン N/3] は保つ）
- canvas: `.chart` 全体に重ね（`aria-hidden`）、backing は CSS px × `min(max(devicePixelRatio, 1), 2)`（`width` / `height` 属性）、見た目の大きさはクラスの CSS。格子の RGBA を nx × ny のオフスクリーン canvas に `putImageData` → 描画域の矩形（device px の整数）へ平滑化して `drawImage`。CSP（`img-src 'self'`）のため `toDataURL`・`<img>`・`createObjectURL` は使わない。色はテーマの解決値が変わるたびに `getComputedStyle` で読み直す（JS に色を直書きしない）
