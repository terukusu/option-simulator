# ADR-0009: 建玉の一覧の画像を AI の中継で読み取る（画像入力の送り方・予約額・保存しない方針）

- 状態: 採択（2026-11-01）
- 日付: 2026-11-01
- 関連: #318、EPIC #303（#299・#301・#302）、#139（構造化した提案）、#338（会話の予約の余裕）、[ADR-0004](adr-0004-ai-spend-counter-firestore.md)、[ADR-0005](adr-0005-ai-oauth-via-agent-sdk.md)、[ADR-0006](adr-0006-ai-agent-sdk-only-and-skills.md)、`docs/design.md` 7.1・13.1 K15 の補足・13.4「AI の中継」の「画像の読み取り」・14 章「画像から建玉を読み取る」

## 背景

- 保有の玉（EPIC #303）を入れるのは、板から足を入れるか手入力で 1 本ずつ。証券会社の画面の **建玉の一覧** のスクリーンショット（主に Android の Chrome）から足の組を読み取り、利用者が確かめてから保有のタブに入れたい（オーナーの依頼。建玉の一覧が本線、損益チャートは後回し）
- 画像には口座番号・氏名・残高などが写りうる。オーナーの指示: 画像をどこへ送り、何を保存し、何を保存しないかを利用者に示す。Anthropic に送るならその旨を示す
- AI の送り口は Claude Agent SDK（同梱の CLI）の 1 本（ADR-0006）。画像を送れるか、送るときに CLI が何をするかは文書化されていない

## 調べたこと（偽の Messages API と同梱の CLI 2.1.283。Anthropic は呼ばない）

- 最後の user の content に image block（base64）を入れて渡すと、CLI はそれを上流へ渡す。**長辺 ≤ 2,000 px かつ生のバイト数 ≤ 約 512,000 B** なら `media_type`・`data` ともバイト一致。超えると CLI が縮めて（長辺 2,000 px に）作り直すか JPEG に作り直す
- CLI は受けた画像を **ディスクに書く**: `$CLAUDE_CODE_TMPDIR`（無ければ OS の一時ディレクトリ）`/claude-<uid>/<cwd の名前>/<session>/images/1.png`。中継の要求ごとの一時ディレクトリの **外** で、要求の後も残る
- CLI は上流への要求の最後の user の末尾に text `[Image: source: <上の画像のパス>]` を 1 つ足す。決まった文の末尾に改行を 1 つ足すことがある
- 読み取りの形（組み込みのツール・スキル・プラグインなし、`max_turns` 1、SDK MCP のツール 1 本）にすると、上流のツールは `mcp__sim__report_positions` の 1 本だけになる
- 公式の文書（vision、2026-11-01 確認）: Claude 4.7 以降の高解像度の段は長辺 2,576 px・1 枚 4,784 visual tokens が上限（トークン ≈ ⌈w/28⌉ × ⌈h/28⌉）。1 枚 10 MB（base64）。形式は JPEG・PNG・GIF・WebP

## 決定

1. **送り口は今の 1 本のまま**（ADR-0006 の例外にしない）。会話とは別の 1 回きりの要求 `POST /api/ai/read_positions`（JSON の 1 往復。SSE にしない = text・thinking をブラウザに流す経路を作らない）。`params["mode"] = "read"` のとき送信先は組み込みのツール・スキル・プラグイン・文書なし、`max_turns` 1、ツールは読み取り専用の `report_positions` 1 本（フックが deny + `continue_=False`）。送るのは読み取りの指示（system。会話の system prompt・スキルとは別の定数）+ 画像 1 枚 + 決まった短い文だけ。板・ポジション・自分の前提は送らない
2. **CLI に作り直させない上限**: 長辺 2,000 px・生のバイト数 500,000 B（観測の境 約 512,000 B から約 2% の余裕）・`image/png` / `image/jpeg`。ブラウザが canvas で描き直して満たし（EXIF などのメタデータも落ちる）、中継がマジックバイトと寸法（PNG の IHDR・JPEG の SOF を自前で読む。依存を足さない）で検査する（違えば 400）。利用者がプレビューで見た画像がそのまま上流に届く。境の内側のバイト一致と外側の作り直しを `api/tests/test_ai_agent_sdk_cli.py` で固定し、SDK（= CLI）の版を上げて境が変わったら検出する
3. **CLI が足す `[Image: source: <パス>]` の text は受け入れる**（オーナー判断 2026-11-01）。パスは要求ごとの一時ディレクトリの名前と uuid だけで、利用者の値を含まない。「送るのは system + 画像 + 決まった文だけ」より 1 block 多いことをここに記録し、結合テストで「1 つだけ・パスが要求ごとの一時ディレクトリの中」を固定する。消すには CLI の内部に手を入れるか送り口を増やす（ADR-0006 の例外）ことになり、割に合わない
4. **画像をディスクに残さない**: 子の環境に `CLAUDE_CODE_TMPDIR=<要求ごとの一時ディレクトリ>/tmp` を入れ（全要求。会話の要求も同じ場所に書くだけ）、要求の後に一時ディレクトリごと消す。結合テストで、要求の後に `claude-*`・`ai-sdk-*` が残らないことを確かめる
5. **予約額**: 今の式（ADR-0006）に T = 1・K = 0・M = `AI_READ_MAX_TOKENS` 6,000（Opus 5.5 は thinking を切れない）。E = 画像の `data` を空にした本文のバイト数 + 余裕 + CLI の分 + 画像 1 枚の上界 `AI_IMAGE_MAX_TOKENS` 4,784（公式の 1 枚の上限 = 寸法から計算しない保守側）。**base64 のバイト数はトークンに数えない**（数えると約 66 万トークン = 約 $5 で必ず 429）。予約は 約 $0.24 / 回（1 日 $3 の 8%）、実額は精算で戻り多くは $0.1 前後。1 日の上限・同時の本数・1 分の回数は会話と共用。会話の予約の式・SKILL.md・会話の system prompt には触れない（#338 に影響しない）
6. **結果は自由な文字列を持たない**: ツールの入力は商品・限月の年 / 月・C/P・行使価格・売買・枚数・建値・建てた日の列挙・数・日付だけ。中継が検査し（知らないキー・自由な文字列・型の不正・行 > 20 → 結果全体を捨てて 502、欄の範囲外 → その欄だけ null）、通った値だけを返す。画像に氏名・口座番号が写っていても、結果・画面・ログに戻る経路が無い
7. **保存しない**: サーバーは画像・結果を保存しない（Firestore には費用だけ。ログは種類・バイト数・寸法・行数・usage・概算費用だけ）。ブラウザは画像・結果をダイアログのメモリだけに置く（Web Storage・IndexedDB・Cache・URL・AI の会話の履歴・作業の保存・書き出しに入れない）
8. **CSP は変えない**: プレビューは送るものと同じ画像の `ImageBitmap` を canvas に描く（`img-src` に `blob:`・`data:` を足さない）。base64 は `FileReader.readAsDataURL` でなくバイト列から作る（data URL を DOM に入れない）
9. **送る前に示す**: [読み取る] の直上に常に見える注意（Anthropic に送ること・扱いは設定した資格情報の規約 / 設定に従うこと・口座番号などは端末で切り取ること・simulator は保存しないこと）。毎回の確認ダイアログにはしない（docs/ui-guidelines.md P3）。送るのは [読み取る] を押したときだけ

## 検討した選択肢

| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. Claude の画像入力（今の送り口。採択） | 証券会社ごとの表の形・列の名前・限月の書き方の違いを吸収できる。依存を足さない。中継の守り（許可リスト・上限・ログの方針）をそのまま使える | 画像が Anthropic に送られる（示す）。1 回ごとに費用（予約 約 $0.24、実額は精算で多くは $0.1 前後）。CLI の内部の振る舞い（上限・一時ファイル・足す文）に依存する（結合テストで検出） |
| B. ブラウザ内の OCR（tesseract.js など） | 画像が端末から出ない | WASM と日本語の学習データで数十 MB の依存。CSP に `'wasm-unsafe-eval'`。文字を拾うだけで、表の列の対応づけを証券会社ごとに作る必要があり壊れやすい。細かい日本語の表の精度が低い |
| C. Messages API を直接呼ぶ送り口を足す（画像だけ） | CLI の作り直し・一時ファイル・足す文が無い | 送り口が 2 本になる（ADR-0006 の一本化を崩す）。`oauth_token`（本番の既定）は直接呼び出しで 429 になる（ADR-0005） |

## 結果

- 良い点: 保有の玉を 1 枚の画像から確認表へ入れられる。読み取りの結果は形の決まった値だけで、確認表で利用者が直してから新しいタブに入る（確かめずに足へ入れる経路は無い）
- 悪い点:
  - 上限（長辺 2,000 px・500,000 B）は CLI 2.1.283 の観測で、文書化されていない。SDK を上げると変わりうる（結合テストで検出し、定数を直す）
  - CLI が足す `[Image: source: …]` の 1 block は消せない（決定 3）
  - [中止] はブラウザが待つのをやめるだけで、サーバーは最後まで読む（費用は精算どおり。締め切り 50 秒で上界）
  - 一時ディレクトリの削除は要求を処理するスレッドの finally なので、ワーカーが SIGKILL（gunicorn の再起動・OOM）で止まると読み取りの途中の画像が `ai-sdk-*/tmp/claude-*/…/images/` に残りうる（既知の性質。会話の要求の一時ディレクトリと同じ。Cloud Run の `/tmp` はインスタンスのメモリ上でインスタンスと一緒に消える）
  - 読み取りの精度（証券会社の画面ごと）は合成の画像では測れない。本番で架空の値で作った画面で確かめる
- 範囲外（第 2 弾以降・別 Issue）: 損益チャートからの読み取り、複数枚の画像、証券会社ごとの専用の解析、画像の切り取りの UI、既存の保有のタブとの突き合わせ
