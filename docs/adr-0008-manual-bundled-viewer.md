# ADR-0008: マニュアルを画面のビルドに同梱し、説明カードの中で節を読む

- 状態: 採択（2026-10-31）
- 日付: 2026-10-31
- 関連: #322、#167（説明カード・「マニュアルはビルド成果物に入れない」）、#320（戻るの規則・説明カードの列）、[ADR-0007](adr-0007-ai-docs-read-tool.md)（節の番号の規則 = 決定 5）、`docs/ui-redesign.md` §5「説明カード」、`docs/ui-guidelines.md` P2・P6・P10・P11

## 背景

- アプリの中で読める説明は ⓘ の吹き出しと用語の説明カードだけだった。説明カードにはマニュアルの節の名前が **文字だけ** で出ていた（#167 で「マニュアルはビルド成果物に入れない」とした）。AI の返答の根拠の節（「マニュアル 8.5「追証マップ」」）もただの文字だった
- オーナーの要望（#322）: マニュアルの節をアプリを離れずに読みたい。戻る挙動（節をたどった分も 1 段ずつ戻る）は #320 の仕組みに乗せる
- ブラウザから文書の節を取る口は無かった（文書はイメージの `/app/docs` に置き、AI の中継だけが読む）
- マニュアル（`docs/user-guide.md`）は約 220 KB・1,500 行の Markdown（画像・HTML なし）

## 決定

1. **文書の取り方 = 画面のビルドに同梱し、初めて要るときだけ読む**。`ui/next/parts/manualDoc.ts` が `import('../../../docs/user-guide.md?raw')` を動的 import し、Vite が別の chunk（`assets/user-guide-<hash>.js`。約 224 KB・gzip 約 70 KB）にする。最初の画面の読み込みには入らない（入口の chunk の増加は描き方のコードの約 14 KB だけ）。サーバー・API・中継・infra は変えない
2. **読み込む時 = 説明カードにマニュアルの節・目次を初めて出したとき**（用語のカードの「マニュアル: …」・ⓘ の「マニュアル:」・⋯ の「マニュアル」・AI の返答の根拠の節を押したとき）。AI の返答を描くときには読まない: 根拠の節は **いつも押せる印** にし、押した後に索引で番号 → 見出しの順に引き、どちらでも見つからなければカードに「マニュアルに見つからない」と見出しの文字を出す（読み込まずに「押せるか」を決められないため。#322 のオーケストレーターの決定）
3. 状態は `idle → loading → ready | error`。読み込み中は「読み込み中」、失敗（デプロイの後の古いタブで古い chunk の名前が 404 など）は固定文「マニュアルを読み込めませんでした。ページを読み直してください」。失敗した動的 import はブラウザが同じ URL で覚えているので再試行しない。例外は外へ出さない
4. **ビューアーの形 = 説明カードの列に積む**（用語と同じ 1 つのカード・1 つの列。`ui/view/termChain.ts` の `CardEntry` = 用語 / 節（アンカー）/ AI の根拠の節（番号と見出し）/ 目次）。戻る・Esc・[← 戻る]・×・外のクリック・本文の位置・フォーカスの決まりは用語と同じ（P2・P6）。別のダイアログは作らない
5. **節の索引と番号**: `ui/view/manual.ts`。番号の規則は AI の索引（`api/src/simulator_api/ai/docs.py` の `parse`、ADR-0007 決定 5）と同じで、TS と Python の **2 か所** にある（今までテストにあった TS の写しを本体に移した）。言語をまたぐ突き合わせは、今のマニュアルの番号のある節（番号・階層・見出し・アンカー）を画面の規則で書いた `fixtures/docs/user-guide-sections.json`（`npm run fixtures` が書き、`npm run fixtures:check` と vitest が TS と一致を確かめる）を、API の pytest（`api/tests/test_ai_docs.py`）が Python の `parse`（アンカーは GitHub の規則を Python で別に書いたもの）と比べて固定する（どちらも CI。見出しを変えたら `npm run fixtures` で作り直す）。見出しの開発の経緯を外す `\b` は Python（Unicode の語の境）に揃えた。ずれたとき（文書が変わった後の古い返答を含む）は見出しで引き直して吸収する。アンカーは GitHub の見出しのアンカーの規則（重複は `-1`…）で、マニュアルの中のリンク・用語の `guide.anchor`・ⓘ の場所 → 節（`HINT_GUIDE`）はアンカーで引く（見出しを変えない限り変わらない）
6. **描き方**: 見出し 2〜4・段落・箇条書き（入れ子 1 段）・番号つき・表・コードブロック・区切り線、行の中は太字・コード・節へのリンクだけを木にし、JSX のテキストで描く。知らない記法は文字のまま。HTML 文字列・`style`・`href` を作らない（P11。CSP の `script-src 'self'` は動的 import の same-origin の chunk で足りる。CSP は変えない）。外へのリンク（README・LICENSE・design.md など）と当たらないアンカーは文字だけ（アプリを離れない）
7. 読めるのはマニュアルだけ。設計書（`docs/design.md`）は画面で読まない（AI の「設計書 5.4」は文字のまま）
8. **イメージ**: `Dockerfile` の画面のステージに `COPY docs/user-guide.md` を足す（`.dockerignore`・`.github/scripts/image.sh` は ADR-0007 で既に含む）。chunk は `.js` なので `image-check.sh`（`/app/static` に JSON が無い）・`csp-check.sh`（index.html と鍵の形）に当たらない

## 検討した選択肢

| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. API で節を返す（AI の索引を流用） | 画面のビルドが軽い | 新しい口・テスト・dev の用意が要る。`DATA_SOURCE=file` や `npm run dev` で中継の文書の置き場が要る |
| B. ビルドに同梱して遅延読み込み（採択） | サーバーを変えない。dev でも読める。画面と文書が同じビルドで食い違わない | 約 220 KB の chunk（初回だけ。immutable でキャッシュ）。#167 の判断を改める |
| C. GitHub のマニュアルへ飛ばす | 作りが要らない | アプリを離れる（スマホで戻れない）。公開していない fork では開けない |

ビューアーの形は、別のダイアログ（2 つの列・2 つの戻る規則になる）・インスペクターのパネル（場所を取り、スマホのシートと重なる）より、説明カードの列（決定 4）を採った。

## 結果

- 良い点: ⓘ → 用語 → マニュアルの節 → AI の順で、説明をアプリの中で引ける（P10）。AI の根拠の節を押して確かめられる。戻るの規則が 1 つのまま
- 悪い点:
  - chunk は Flask の静的配信で gzip されずに配られる（約 224 KB。前段で圧縮されるかは未確認）。初回だけで、`/assets` は immutable
  - 番号の規則が 2 か所（決定 5。ずれは fixtures と pytest で CI が止める）。マニュアルの見出しを足すと AI の返答の番号がずれる（見出しで引き直して吸収）
  - デプロイの後に開いたままの古いタブは、古い chunk が無ければ固定文になる（読み直せば直る）
  - AI の根拠の節は押すまで在るかが分からない（見つからなければカードに出す）
- 戻し方: PR の revert → deploy。保存の形式・API は変えないので、データの戻しは要らない

## 確かめ方

- vitest: `tests/ui/manual.test.ts`（番号が `docSections` = AI の規則と同じ・`ASK_DOCS` の節・マニュアルの全部のリンク・用語の 25 語・`HINT_GUIDE`・全節を描ける）、`tests/ui/manualRefs.test.ts`（根拠の節の拾い方・番号 → 見出しの引き方）、`tests/ui/termChain.test.ts`（混ざった列）
- 画面: `npm run ui:check -- --manual`（`--flows` にも入る）。最初の画面の読み込みにマニュアルが入らない・遅いと「読み込み中」・読めないと固定文、戻る / Esc / [← 戻る] の 1 段ずつ・本文の位置・フォーカス、360px で表とコードが枠の中だけ横に送られる
- `npm run build` の出力で入口の chunk にマニュアルの文が入っていないこと（別の chunk `user-guide-*.js`）。`npm run pwa:check` で節を開いても CSP 違反 0
