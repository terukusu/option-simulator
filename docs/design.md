# option-simulator 設計メモ

日経225オプションの **建てる前の戦略検討** に使う損益シミュレーター。optionchan（JPX のページから毎分取り込んだ価格・IV を BigQuery に蓄積するツール）の最新の板を初期値に使う。保有管理・発注は対象外。

状態: リファイン 1 回目（2026-10-13）。「8. 置き場所」は未決定で、比較と推奨を書いた。損益シミュレーター（MVP、2 章）の後にプレミアムシミュレーター（11 章）を置く。オーナー判断が要る項目は「13. リスクと未決事項」にまとめた。変更点は末尾の「変更履歴」。

リポジトリは誰でも clone して自分の環境で使える汎用の作りにする（プロジェクト ID・リポジトリ名・メールを埋め込まない。例は `<PROJECT_ID>` 等のプレースホルダ）。

## 1. なぜ作るか（差別化）

既存ツール（証券会社のシミュレーター等）への不満と、この PJ での扱い:

| 既存ツールの不満 | この PJ | 根拠・実現手段 |
|---|---|---|
| IV を全行使価格で 1 つにする（スマイルを無視）。OTM 売りのリスクが小さく見える | **行使価格ごとの IV** で評価する | optionchan に行使価格ごとの `bid_iv` / `ask_iv` / 約定 IV がある（4 章） |
| 行使価格・価格を毎回手で入れる | **最新の板を自動で読み込み**、板・スマイルカーブのクリックで足を追加 | optionchan の最新スナップショット（API 1 回、7 章） |
| シナリオが「今」と「満期」だけ。日数・原資産・IV を同時に動かせない | 経過日数・原資産・IV 水準・スキューの **4 スライダーを同時に** 動かす | 計算はブラウザ内（5 章）。描き直しに通信しない |
| 戦略を並べて比べられない | 後段（12 章）で複数戦略の重ね描き・指標の横並び | ポジションを URL / ローカルに保存できる形にしておく（6 章） |
| 操作のたびに再読み込みで重い | 板の読み込み以外は通信ゼロ。描き直し 16 ms 以内が目標 | Canvas 描画（10 章） |
| 夜間は現物（日経平均）が止まっていて評価できない | **先物ベース（Black-76）** なので夜間も評価できる | 夜間は `spot_price` が 15:45 で止まる（4.3） |
| 表示範囲が ATM 周辺に固定で、**ファー OTM**（小資金で扱う 20〜40% OTM の put など）が見えない・小さい損益が潰れる | グラフ・スマイル・板の **スケールとスクロールを必須**にする（M10）。遠い行使価格まで横軸を広げ、縦軸を数円単位まで拡大できる | 4.5 の実態（1 限月 put は 40% OTM まで気配がある）に合わせる |
| 行使価格 × IV のプレミアム表（証券会社のツールにある）が、板と切り離されていて現在の板と比べられない | **プレミアムシミュレーター**（11 章。MVP の後）。板の値を初期値にし、板の bid / ask / IV を表の横に並べて比べる | 価格モデル・データ・UI 部品を損益シミュレーターと共通化 |

## 2. スコープ

### 2.1 MVP（最初に作るもの）

| # | 機能 | 内容 |
|---|---|---|
| M1 | 板の読み込み | optionchan の最新スナップショット（2 限月分）。原資産（日経平均・先物）、行使価格ごとの call / put の価格・bid / ask・IV・JPX 公表グリーク。**ATM は最新の期近先物の価格から動的に判定**（5.9。JPX ページの ATM 表示 `is_atm` は使わない）。鮮度（スナップショット時刻・先物の約定時刻）を常時表示 |
| M2 | スマイルカーブ | 限月ごとに moneyness 軸で bid / ask / mid の IV を描く。欠損の補間結果（5.3）を点線で区別 |
| M3 | ポジションの組み立て | 板・スマイルから足を追加（売買・枚数・建値は板の値を初期値に編集可）。**足ごとに商品（ラージ OP / ラージ先物 / ミニ先物 / マイクロ先物）と限月を選べる**（オプションはラージだけ。決定 K1）。**先物の足は MVP で必須**で、既定の先物は **ミニ先物**（K6。建値の初期値は板の先物価格、5.8）。限月の違う足の組み合わせ（カレンダー）も可。板の無い限月・商品は手入力（5.7）。手入力の足も可 |
| M4 | 損益グラフ | 横軸 = 原資産（SQ 値 / 先物）。満期（SQ）損益と、指定日の理論損益を重ねる |
| M5 | シナリオ | スライダー 4 本: 経過日数、原資産の変化、IV の平行移動、スキューの傾き。IV の動き方（sticky strike / moneyness）を切り替え |
| M6 | 指標 | 損益分岐点、最大利益 / 最大損失（無限なら明示）、ポジション合計のデルタ・ガンマ・セータ・ベガ、受け払いの合計（ネットのプレミアム） |
| M7 | 戦略テンプレート | ストラングル / ストラドル（売り・買い）、バーティカル、アイアンコンドル、バタフライ、カレンダー、レシオ。ATM（5.9 の動的 ATM）・ATM から n 本・デルタ・距離（σ 倍・円）で行使価格を選んで一括で組む |
| M8 | 保存 | ポジションとシナリオをブラウザ（localStorage）と URL（圧縮 JSON）に保存。板のスナップショット時刻も一緒に残す |
| M9 | データ元の切替 | `bigquery`（本番）/ `file`（JSON。GCP を持たない人・オフライン・テスト）/ 手入力 |
| M10 | **スケールとスクロール（必須）** | 損益グラフ・スマイルカーブ・板の 3 つで拡大縮小とパン。損益グラフ: 横軸の範囲は上場している最遠の行使価格まで、縦軸は自動（表示中の足に合わせる）と手動（円〜千円単位）。操作はホイール・ピンチ・ドラッグ、ダブルタップ / ボタンでリセット。スマイル: 横軸を行使価格 / moneyness / デルタで切替、翼を拡大。板: 行使価格の一覧を ATM に戻すボタンと、OTM 側へのスクロール（322 行でも軽い） |
| M11 | ファー OTM の扱い | 価格が小さい行（ask 5 円以下など）の IV に「不安定」の印、翼の外挿の明示（5.3）。指標の表示単位を受け払いの大きさに合わせて円 / 千円で切り替える（5.6） |
| M12 | **デルタヘッジ補助** | ポジション合計のデルタを **ラージ先物換算とミニ先物換算の両方**で表示。目標デルタ（既定 0）にするのに必要なミニ / ラージ先物の枚数を提示し、ワンクリックで足に追加。丸めた後に残るデルタを表示（5.8） |

### 2.2 受け入れ基準（AC）

| AC | 検証方法 |
|---|---|
| AC1 板: 取引時間中に開くと、optionchan の最新スナップショット（15 分遅れ、4.3）が 3 秒以内に表示され、時刻・限月（取引最終日と SQ 日）・先物の限月が見える | ブラウザで計測（コールドスタート除く）。API のテストで JSON の形を固定 |
| AC2 板: 寄り前・時間外は「直前の引けの板」に自動で切り替わり、その旨を表示する（4.3） | 16:45〜17:00 JST と土日に開いて確認。API の単体テストで判定ロジックを固定 |
| AC3 価格: Black-76 の価格・IV・グリークが参照値と一致する（価格 0.01 円、IV 1e-6、グリークは有限差分と 1e-4） | 単体テスト（既知の値 + パリティ恒等式） |
| AC4 IV: 板の ATM ±10% の行は補間なしで IV が決まり、欠損行は近傍から補間した値に「補間」の印が付く | 固定の板 JSON でスナップショットテスト |
| AC5 F: 限月ごとの原資産 F（PCP 合成先物、5.1）が、板の ATM ±4% の全ペアから求めた値の中央値と一致し、先物の限月が合わない月でも決まる | 単体テスト。実データ 1 日分でも手で確認（JPX の IV との差が ATM 近辺で RMSE 0.5pt 以内） |
| AC6 損益: 満期損益の折れ点が行使価格と一致し、満期の損益分岐点が解析的な値（1 円単位）と一致する | 単体テスト（各テンプレート） |
| AC7 指標: ポジション合計のデルタ・セータ・ベガの符号と桁が、JPX 公表グリークから合算した値と整合する（デルタ ±0.05 枚、ベガ ±10%） | 実データで照合するテスト（`file` アダプタの固定 JSON） |
| AC8 スライダー: 4 本を動かしたときの描き直しが 16 ms 以内（原資産 200 点 × 足 10 本） | ブラウザの Performance で計測。CI では計算部分のベンチ |
| AC9 テンプレート: 「2 限月、1σ 外のストラングル売り」を 3 クリック以内で組める | ユースケース U1（6.2）を手で通す |
| AC10 スマホ: 幅 360px で板・グラフ・スライダーが横スクロールなしで使える | iOS Safari / Android Chrome で確認 |
| AC11 セキュリティ: `allUsers` に公開せず（A 案なら IAP）、CSP 違反がコンソールに出ない | Terraform のテスト、ブラウザのコンソール |
| AC12 汎用: clone した人が README の手順でローカル（`file` アダプタ）と自分の GCP で動かせる。リポジトリにプロジェクト ID・メールが無い | README の手順どおりに別環境で実行。`grep` のテスト |
| AC13 スケール（損益グラフ）: 横軸を F ±5% から **板の最遠の行使価格**（例: F −45%〜+33%）まで連続に広げ縮められ、縦軸を自動と手動（最小 100 円刻み）で切り替えられる。ホイール・ドラッグ（PC）、ピンチ・ドラッグ（スマホ）、リセット操作の 3 つが効く | ブラウザで操作。描画の範囲計算は単体テスト（範囲のクランプ、リセット値） |
| AC14 スケール（スマイル・板）: スマイルの横軸を行使価格 / moneyness / デルタに切り替え、翼（20% OTM 超）を拡大しても補間 / 外挿の印が区別できる。板は 322 行の限月でも 1 画面にスクロールで収まり、「ATM へ戻る」で ATM 行が見える | ブラウザで操作（PC・スマホ）。板のレンダリングは仮想化なしで 16 ms 以内 |
| AC15 小さい損益: 受取プレミアムが 10 千円未満のポジション（例: 30% OTM put 売り 1 枚 @ 30 円 = 30 千円…以下の少額の買い）でも、縦軸の手動スケールで折れ点と BEP が見え、指標は円単位で表示される | 固定の板でユースケース U4 を手で通す |
| AC16 ファー OTM の IV: ask が 5 円以下、または `ask_iv − bid_iv` が 5pt 超の行は「IV 不安定」の印が付き、足にしたときに警告が出る。翼の外挿値はスマイル上で区別され、外挿で評価した足にも印が付く | 固定の板でスナップショットテスト |
| AC17 商品と限月: 足ごとに商品と限月を選べ、乗数（1,000 / 100 / 10）と SQ 日が損益・指標に正しく反映される。1 限月売り + 2 限月買い（カレンダー）と、ラージ OP + ミニ先物の組み合わせが組める。板の無い限月・商品の足は「板なし（手入力）」の印が付き、板がある足と同じグラフに重なる | 単体テスト（乗数・SQ・満期評価）。固定の板でユースケース U3 と「ラージ OP + ミニ先物」を通す |
| AC18 デルタの単位: 指標のデルタがラージ先物換算（`Σ 枚数 × δ × 乗数 / 1,000`）とミニ先物換算（× 10）の両方で出て、ラージ OP 1 枚 δ 0.5 の買い = ラージ換算 +0.5 / ミニ換算 +5.0、ミニ先物 1 枚の買い = +0.1 / +1.0、マイクロ 1 枚 = +0.01 / +0.1 になる | 単体テスト |
| AC19 デルタヘッジ: 「ヘッジ」を押すと、現在のポジションのデルタを目標（既定 0）にするミニ先物の枚数（四捨五入）と、ラージで行う場合の枚数が出る。追加すると足（既定: ミニ先物、直近四半期限月、建値 = 板の先物価格）が入り、合計デルタが目標 ±0.05（ラージ換算。ミニ 1 枚の半分）以内になり、残りのデルタが表示される。目標デルタを変えても同じ | 単体テスト（枚数の丸め・残り）と、固定の板でユースケース U5 |
| AC20 ATM: 板・スマイル・テンプレートの ATM が「最新の期近先物の価格に最も近い行使価格」になり、先物価格を変えた固定の板で ATM が追随する。JPX の `is_atm` と違う行でも先物基準の行が ATM になる。同距離のときの規則（5.9）どおり。シナリオの原資産を動かすと「シナリオ ATM」の印がグラフとスマイル上で動き、板の ATM（市場）は動かない | 固定の板でスナップショットテスト（先物価格を 3 通り変える）。実データで `is_atm` との不一致を 1 日分数えて記録 |

### 2.3 スコープ外（MVP では作らない）

発注・口座連携、保有ポジションの管理・損益の記録、バックテスト、証拠金の正確な計算（VaR 方式。目安の優先度は D10）、日経225ミニオプション（決定 K1。後段で、optionchan にミニのページの取り込みを足す案と合わせて検討）、マイクロのオプション（JPX に無い。決定 K2）、3 限月以降の板の自動読み込み（手入力 / 理論値で扱う。5.7）。

### 3.1 商品の体系（このツールで選べる商品）

JPX の商品一覧（2026-10-13 に確認）にある日経225の商品は、先物 3 つ（日経225先物・日経225mini・日経225マイクロ先物）とオプション 2 つ（日経225オプション・日経225ミニオプション）。**マイクロのオプションは一覧に無い**ので扱わない（決定 K2。マイクロは先物の足としてだけ）。オプションは当面ラージだけ（決定 K1）。

| 商品 | 種類 | 乗数 | 限月の体系 | SQ | optionchan の板 |
|---|---|---|---|---|---|
| 日経225オプション（ラージ） | オプション | 1,000 | 月次（毎月第 2 金曜）。四半期限月は最長 8 年、その他は直近 8 か月 | 第 2 金曜 | **直近 2 限月のみ** |
| 日経225ミニオプション（**後段**。K1） | オプション | 100 | 週次（金曜限月: 第 2 金曜のもの直近 3 + それ以外の金曜 直近 4、水曜限月 直近 4） | 毎週の金・水曜 | 無し。後段で optionchan にミニのページの取り込みを足す案と合わせて検討 |
| 日経225先物（ラージ） | 先物 | 1,000 | 四半期（3・6・9・12 月） | 第 2 金曜 | 直近四半期限月の価格 1 本 |
| 日経225mini | 先物 | 100 | 四半期（最長 5 年）+ その他の月（直近 3 か月） | 第 2 金曜 | 無し（ラージの価格で代用。同じ原資産・同じ SQ） |
| 日経225マイクロ先物 | 先物 | 10 | 要確認（制度概要ページで未取得） | 第 2 金曜 | 無し（同上） |
| マイクロのオプション | — | — | 商品一覧に無い。**扱わない**（K2） | — | — |

要確認（実装前に JPX の規程で確かめる）:

- 取引最終日の **夜間セッション**で、満了する限月は取引されるか（T の終端を「取引最終日 15:45」にする設定を残す理由）
- 日経225ミニオプションの限月の追加（2026-03 のパブリックコメントで月・火・木限月の案。実施の有無）
- 日経225マイクロ先物の限月の設定
- ミニ先物の毎月限月（四半期以外）と、同じ月のラージのオプションの SQ が同じ日であること（先物の足の満期評価で使う）
- 先物の呼値（ラージ 10 円、ミニ 5 円（制度概要ページで確認）、マイクロ 5 円は要確認）。建値の入力の丸めにだけ使う

## 4. データの実際（optionchan）

コード（`apps/ingest` のパーサー・`snapshot.py`・`calendar.py`）、スキーマ（`schema/tokyo/*.json`）、BigQuery の直近データ（2026-10-13、読み取りのみ。件数・割合だけを書く）から確認した。

### 4.1 テーブルと列

データセット `optionchan_tokyo`（東京）。表示・集計は **テーブル関数** `latest_runs` / `spot_price_latest` / `future_price_latest` / `option_price_latest(start_at, end_at)` で読む（回収・再処理の重複と書き込み途中の残骸を除いた最新版。期間引数は必須。`option_price` は `created_at` の日次パーティションで `require_partition_filter`）。

### 4.2 限月と先物の限月

- オプションは JPX のページの **1 限月・2 限月**（例: 10 月中旬なら 11 月限と 12 月限）。3 限月以降は無い
- 先物は **ラージの直近四半期限月 1 本**（例: 10 月中旬は 12 月限）。両ページとも同じ先物で、`contract_month` は表示の年月（`date(YYYY, MM, 1)`）
- したがって **オプションの限月と先物の限月は原則ずれる**: 1 限月が一致するのは 3・6・9・12 月、2 限月が一致するのは 2・5・8・11 月。残りの月は両方ずれる。→ 原資産 F は先物をそのまま使えない（5.1 で解決）

### 4.3 時間と鮮度

- スナップショットは **立会時間中（日中 8:45〜15:45、夜間 17:00〜翌 6:00）+ 終了後 30 分**だけ。時間外・休業日は新しい行が無く、最新は直前の立会の最後（引け後 30 分間は板が凍った同じ内容）
- `created_at` は **ページの更新時刻**で、実時刻より **約 15 分遅い**（ページの仕様。21:46 JST 時点の最新が 21:31）。画面にはこの時刻を出し、「約 15 分遅れ」を明記する
- **寄り前は板が壊れている**: 夜間の寄り前（16:45〜17:00）は行数が 1/10 で価格・IV が全て NULL、気配も片側だけ。日中の寄り前（8:39〜8:50）は行数は揃うが気配が片側のみ。→ 「使える板」の判定（7.2）が要る
- 夜間は **現物（日経平均）が 15:45 で止まる**。先物は動く。→ 原資産を現物にすると夜間は評価できない（Black-76 を選ぶ理由）
- 休業日（祝日取引の無い日）・取り込みの欠落で、最新スナップショットが数日前のこともある。探索範囲は optionchan のビューアーと同じ **14 日**

| 1 限月 call | ATM ±5% | 16% | 100% | 100% | 100% | 150 |
| 1 限月 put | ATM ±5% | 16% | 100% | 100% | 100% | 166 |
| 1 限月 call / put | 5〜10% | 12〜20% | 86〜100% | 100% | 100% | 229〜263 |
| 1 限月 call / put | 10〜20% | 25〜34% | 66〜93% | 91〜100% | 91〜100% | 146〜332 |

| 1 限月 put | 20% 超 | 42% | 94% | 94% | 94% | 5 |
| 2 限月 call / put | ATM ±10% | 2〜4% | 100% | 100% | 100% | 123〜305 |

| 2 限月 call | 20% 超 | 1% | 4% | 4% | 4% | — |

読み方:

- `iv`（JPX の IV）は **その日の約定があった行にしか無い**（`price` と同時に NULL）。ATM 近辺でも 2〜16%。→ **IV の主な出典は `bid_iv` / `ask_iv`** にする。ATM ±10% ではほぼ 100% ある
- `bid_iv` が `bid` より少ないのは、bid が 1〜2 円など極端に小さいとき（IV が計算されていない）
- **JPX ページの ATM 表示（`is_atm`）は日中も夜間も動く**（2026-10-13 は 1 時間に 2〜5 本の行使価格を移った）が、基準が分からない: 先物価格に最も近い行使価格と一致するのは時間帯により 1〜5 割（日中は現物寄り、夜間は現物が止まっているのに動く）。→ このツールでは **使わない**（5.9）。日中の終値で固定されているわけではないが、先物基準でもない
- 深い OTM の call は気配自体が無い（売り手がいない）。put の深い OTM は 1〜数円の気配が付く。補間 / 外挿が要るのはこの領域で、ATM 近辺は不要
- スプレッドは夜間の数字で、IV 換算で ATM ±5% が 1.2〜2.4pt、5〜10% で 3〜5pt。mid を使うとこの幅の中の 1 点を選ぶことになる（建値側の IV を使うオプションの理由）
- 行使価格の刻み: ATM ±10% が **125 円**、その外が 250 円、さらに外は 500〜2,500 円の飛び（上場が疎）

|---|---|---|---|---|---|---|---|
| 1 限月 put | 10〜20% | 29 | 100% | 218 / 232 | 31〜42% | 0.5 / 1.7pt | 2.6 万 |
| 1 限月 put | 20〜30% | 27 | 100% | 68 / 72 | 42〜55% | 0.5 / 0.8pt | 1.7 万 |
| 1 限月 put | 30〜40% | 17 | 100% | 28 / 38 | 55〜68% | 2.2 / 4.2pt | 1.1 万 |
| 1 限月 put | 40% 超 | 17 | 100% | 5 / 6.5 | 69〜117% | 2.9 / 7.7pt | 1.2 万 |
| 1 限月 call | 10〜20% | 15 | 100% | 84 / 91 | 24〜25% | 0.4 / 0.9pt | 0.6 万 |
| 1 限月 call | 20〜30% | 3 | 100% | 3 / 4 | 25〜29% | 1.0 / 1.5pt | 0.1 万 |
| 1 限月 call | 30% 超 | 1 | 0%（ask のみ） | — / 1 | 30% | — | 0.04 万 |
| 2 限月 put | 30〜40% | 28 | 100% | 66 / 80 | 46〜57% | 1.6 / 2.7pt | 2.3 万 |

| 2 限月 call | 20〜30% | 6 | 100% | 36 / 49 | 23〜25% | 1.2 / 1.4pt | 0.5 万 |

読み方:

- **put の翼は 1 限月なら 40% OTM まで両側気配が揃い、IV も取れる**（price は 5〜70 円）。小資金で扱う「20〜40% OTM の put 売り」はデータ上は評価できる。建玉もこの帯に厚い
- **call の翼は上場自体が薄い**（20% 超は 3〜6 本、30% 超は 1 本で片側気配）。call 側の外挿はほぼ必ず要る
- **2 限月の 40% 超の put は使えない翼**（気配が片側・無しが大半、bid 1 円 / ask 45 円のような板）。IV は意味を持たない
- **呼値 1 円が IV で 1〜3pt に相当**する（ask 20 円以下の行で、スプレッド 1 円のとき `ask_iv − bid_iv` が 1 限月で平均 1〜3pt、2 限月の深い翼では 4 円で 14pt）。低価格の IV は不安定で、IV を 1pt 動かしても価格は 1 円も動かない。→ ファー OTM の足は「IV の数字」より「価格（円）と呼値」で見せる。IV の不安定さの印は `ask ≤ 5 円` または `ask_iv − bid_iv > 5pt`（AC16）
- 翼の IV 水準は put で急（1 限月: 10% OTM 31% → 40% OTM 69〜117%）。水平外挿（5.3）は翼の内側では IV を **過小**に見積もるので、外挿した評価値には必ず印を付ける

### 4.6 JPX の IV・グリークの計算方法（照合の結果）

JPX（ページの提供元）の計算方法は公開されていない。1 スナップショット（上記）で Black-76 と照合した:

- 原資産 = 12 月先物、T = SQ 日 9:00 までの暦日 / 365 で、2 限月（12 月限）の `ask_iv` は **RMSE 0.13pt** で再現できる（限月が一致）
- 1 限月（11 月限）は 12 月先物をそのまま使うと RMSE 0.60pt。**PCP 合成先物（5.1）を使うと 0.22pt** で、最良の F（0.22pt）とほぼ同じ。= JPX は限月ごとの理論先物（合成先物相当）を使っていると読める
- T の終端を取引最終日 15:45 にすると悪化する（0.55pt）。→ **SQ 日 9:00** を既定にする
- 公表グリークは参考値（照合用）にとどめ、計算は自前で行う（シナリオで動かすため）

## 5. 価格モデル

計算はすべてブラウザ（TypeScript）。サーバーは板の JSON を返すだけ。

### 5.1 原資産 F の決め方（限月ごと）

| 案 | 内容 | 長所 | 短所 | 判定 |
|---|---|---|---|---|
| (a) 先物をそのまま | `future_price.price`（直近四半期限月） | 単純。夜間も動く | 限月がずれる月（年 8 か月）は金利分のずれ（1 か月で約 50〜100 円、IV 換算 0.3〜0.6pt）。先物の限月交代の前後で飛ぶ | フォールバック |
| (b) 現物 + キャリー | `S × exp((r − q) T)` | 先物が無くても決まる | 配当利回り q の推定が要る。**夜間は S が止まる** | 使わない（夜間に使えない） |
| **(c) PCP 合成先物** | 限月ごとに `F = K + (C_mid − P_mid) × exp(rT)` を ATM ±4% の全行使価格で求め、**中央値** | その限月の市場が織り込む先物そのもの。JPX の IV と最も整合（4.5）。夜間も動く | 気配が両側に無いと決まらない（寄り前）。スプレッドが広いと ±数十円ぶれる | **既定** |
| (d) 先物 + 限月差の補正 | (a) に (c) で推定した basis を足す | (c) が決まらない時の補間に使える | 実装が増える | 後段で検討 |

既定: **(c)**。ATM ±4% で bid・ask が両側にあるペアが 5 組未満なら (a) にフォールバックし、画面に「F = 先物（限月違い）」と表示する。外れ値（スプレッドが ATM 平均の 3 倍超のペア）は除く。2026-10-13 の実測では (c) の 11 月限 F は 12 月先物より 70 円低く、全ペアの範囲は 200 円（夜間）。

### 5.2 時間

- `T = (SQ 日 09:00 JST − 評価時刻) / 365`（暦日）。SQ 日 = `last_trading_day` の翌営業日（optionchan の取引カレンダーで求める。MVP は「翌日が土日・休業日なら次の営業日」）
- 評価時刻の既定はスナップショット時刻（`created_at`）。シナリオの「経過日数」は評価時刻にその日数を足す
- 営業日ベース（休業日の時間価値を割り引く）は設定で切り替えられるようにするが、MVP は暦日のみ。実装時の決め事とする（JPX の IV と整合するのは暦日。4.5）
- 取引最終日 15:45 を終端にする設定は残す（3 章の要確認が解決したら不要なら消す）

### 5.3 IV（出典・補間・欠損）

- 行ごとの IV の優先順: **mid**（`(bid_iv + ask_iv) / 2`。両方あるとき）→ 片側だけあればそれ → `iv`（約定。`price_time` がそのスナップショットの立会内のときだけ）→ 補間
- 「建値側の IV」オプション: 買いは `ask_iv`、売りは `bid_iv`。既定はオフ（mid）。4.4 のスプレッドの幅を使う人が意識できるよう、スマイルに bid / ask を薄く描く
- 補間: moneyness `x = ln(K / F)` に対して、既知の点の **区分線形**（MVP）。不安定な点（4.5 の印が付く行）は補間の節点から外し、スプレッドの狭い点だけで翼を作る。補間 / 外挿した値には印を付け、板にもスマイルにも区別して出す。後段で SVI などの当てはめに置き換えられるよう、補間器はインターフェースにする
- 翼（ウィング）の外挿（最遠の安定な節点より外）: 候補は (i) **水平**（端の値。IV を勝手に上げない。put の翼の内側では過小）、(ii) **端の傾きを延長し、上限 / 下限でクランプ**（put の急な翼に追随するが、傾きが 1 点のノイズで振れる）、(iii) SVI 等の当てはめ（後段）。MVP は **(ii) を既定、(i) を切替**にし、どちらも外挿の印を付ける。外挿が要るのは主に call の翼（上場が薄い）と 2 限月の 40% 超の put（使えない翼）で、1 限月の put は 40% OTM まで実際の気配を使える（4.5）
- 低価格の IV の不安定さ: 価格 5 円以下の行は IV の 1pt が価格 1 円に満たない。足の評価は IV ではなく **価格を直接**扱う（建値は板の円、シナリオの IV 変化を価格に戻すときは呼値 1 円に丸めない）。シナリオで IV を下げて価格が 0 円以下になる足は 0 円で止める
- 限月ごとに別のスマイル（2 本）。限月間の補間は要らない（扱うのが 2 限月だけ。カレンダーも各限月の値を使う）

### 5.4 シナリオ

| スライダー | 意味 | 計算 |
|---|---|---|
| 経過日数 d | 評価時刻を d 日進める | `T' = T − d / 365`。SQ を過ぎた足は満期損益 |
| 原資産 ΔF | F を動かす（円 or %） | `F' = F + ΔF`。グラフの横軸は常に F' を掃く |
| IV 平行移動 Δσ | 全行使価格の IV に加える（pt） | `σ'(K) = σ(K) + Δσ` |
| スキューの傾き Δs | moneyness 当たりの傾きを変える | `σ'(K) = σ(K) + Δs × ln(K / F)` |

IV の動き方（切替）:

- **sticky strike**（既定）: 原資産が動いても `σ(K)` は変えない。単純で説明しやすい
- **sticky moneyness**: 原資産が F' に動いたら `σ'(K) = σ(K × F / F')`（スマイルが原資産と一緒に動く）。指数オプションで下落時の put IV 上昇を表せる。補間器が要る（5.3）

### 5.5 満期損益と SQ

- 満期（SQ）の損益は横軸を **SQ 値**として `max(SQ − K, 0)` / `max(K − SQ, 0)` で評価する
- 先物の足の満期評価は 5.8
- 「指定日の理論損益」は Black-76（残存 T'）。SQ を過ぎた限月の足は満期損益、残る限月の足は理論値（カレンダー）

### 5.6 グリークと損益

- Black-76 の解析解。表示単位: デルタ = **ラージ先物換算**（`Σ 枚数 × δ × 乗数 / 1,000`）と **ミニ先物換算**（× 10）の両方（5.8）、ガンマ = F が 100 円動いたときのデルタの変化、セータ = 1 暦日あたり円、ベガ = IV 1pt あたり円
- 損益 = `Σ 枚数 × 乗数 × (評価価格 − 建値) × 売買符号 − 手数料`
- 金利 r は割引（`exp(−rT)`）と PCP にだけ使う。既定 0.5%（設定で変更）。T = 1 か月なら価格への影響は 0.05% で無視できる
- 手数料: MVP は **1 枚あたり円**（既定 0）。後段で約定代金の割合・SQ 決済の有無を足す。ファー OTM（数円〜数十円）では手数料が損益の数割になるので、指標の「受取 / 支払プレミアム」は手数料込みと抜きの両方を出す
- 小さい損益の見え方: 指標の単位は受け払いの合計が 10 万円未満なら **円**、以上なら千円（自動。手動で固定も可）。売りの「最大損失 ∞」の横に、**原資産が −10% / −20% / −30% 動いたときの損失**（SQ 評価）を並べる（小資金の売りで効くのは「∞」ではなく現実的な下落幅の損失）。少額の買いは「掛け金 = 支払プレミアム + 手数料」と「X 倍になる原資産」を出す
- 乗数は足の商品（5.7）で決まる: ラージ OP / ラージ先物 1,000、ミニ先物 100、マイクロ先物 10

### 5.7 限月と商品の選択（データの制約と代替）

足（損益）と対象（プレミアム）は **商品 × 限月** で指定する。optionchan の板があるのは **ラージのオプションの直近 2 限月と、ラージ先物の直近四半期限月 1 本だけ**なので、それ以外は代替が要る。

| 商品 × 限月 | 板 | 扱い | 段階 |
|---|---|---|---|
| ラージ OP、1・2 限月 | あり | 自動読み込み（M1） | MVP |
| ラージ先物（直近四半期）、ミニ先物・マイクロ先物の同じ限月 | ラージの価格 | 乗数だけ変える | MVP |
| ミニ先物の毎月限月、ラージ / ミニ先物の先の四半期限月 | 無し | **建値を手入力**（初期値は直近の先物価格）。満期評価は限月の SQ で | MVP（手入力） |
| ラージ OP の 3 限月以降 | 無し | (a) **手入力**: 行使価格・建値・IV を入れる（MVP）。(b) **理論値で代用**: IV は 1・2 限月のスマイルから補間（ATM は総分散 `σ²T` の線形補間 / 外挿、スマイルは正規化 moneyness `ln(K/F) / (σ√T)` で写す）、F は先物 + basis 0。「理論値（板なし）」の印を付け、建値は編集可（段階 2）。(c) **optionchan の取り込みを足す**: 3 限月以降のページを取り込む（optionchan 側の Issue。ページの有無・形式は要確認。段階 3） | (a) MVP、(b) 段階 2、(c) 要オーナー判断（D12） |
| ミニ OP（週次限月を含む） | 無し | **後段**（K1）。optionchan にミニのページの取り込みを足す案と合わせて検討。第 2 金曜の限月はラージと同じ SQ なので、ラージの板 × 100 で評価する近道がある | 後段 |

- 限月の一覧は板の限月に加えて、取引カレンダーから **先の月次限月（最長 12 か月）** を生成して選べるようにする（SQ 日 = 第 2 金曜の翌営業日の規則。3 章）。板の無い限月は一覧で「板なし」と表示。ミニ OP を後段で足すときに週次限月（金・水曜）を同じ仕組みで生成する
- 指標・損益はすべて乗数込みの円なので、商品が混ざっても足し合わせられる。デルタの単位は 5.8
- 板の無い足の警告: 「板なし。理論値 / 手入力の値で評価しています」をグラフと指標に出す

### 5.8 先物の足とデルタヘッジ

先物の足は MVP で必須（K6）。用途は「デルタ 0.5 をヘッジする」ような微調整で、既定の先物は **ミニ先物**。

**価格**

- optionchan の `future_price` は **ラージの直近四半期限月 1 本**（4.2）。足の建値の初期値はこの価格で、ミニ / マイクロの同じ限月も同じ価格を使う（同じ原資産・同じ SQ。実際の価格差は呼値程度）。別の限月（ミニの毎月限月、先の四半期限月）は板が無いので手入力（初期値はこの価格。「板なし」の印）
- 足の価格は、その先物の限月 m とオプションの評価用 F（限月ごとの PCP 合成先物、5.1）の差 `basis_m = Fut_m − F` を **一定**とみなし、シナリオの原資産 F' に対して `Fut_m' = F' + basis_m` とする。basis は足を追加した時点の値を初期値に、編集できる（0 にもできる）
- 損益 = `枚数 × 乗数 × (Fut_m' − 建値) × 売買符号`。呼値（ラージ 10 円、ミニ 5 円、マイクロ 5 円。要確認）は建値の入力の丸めにだけ使う

**満期（オプションの SQ）での評価**

| 先物の限月 m とオプションの限月 | 扱い |
|---|---|
| 同じ | SQ 値で最終決済: `Fut = SQ` |
| 先物が後（例: 11 月限 OP + 12 月限先物） | 先物はまだ生きている。`Fut = SQ + basis_m`（basis 一定。既定の近似。basis 0 の切替も可） |
| 先物が先（例: 12 月限 OP + ミニ 11 月限先物） | 先物が先に SQ で決済される。原資産の経路は評価値で平らと仮定し、`Fut = 横軸の値`（単純化。印を付ける） |

**デルタの単位**

- 足 i のデルタ（ラージ先物換算）= `枚数_i × δ_i × 乗数_i / 1,000`。オプションの δ は Black-76、先物は δ = 1
- 例: ラージ OP 1 枚（δ 0.5）の買い = +0.5、ミニ先物 1 枚の買い = +0.1、マイクロ 1 枚 = +0.01
- 指標はポジション合計を **ラージ先物換算とミニ先物換算（× 10）の両方**で出す（例: 「Δ −0.47 枚（ラージ）= −4.7 枚（ミニ）」）。ガンマ・セータ・ベガは円（乗数込み）

**デルタヘッジ補助（M12）**

1. 目標デルタ（ラージ換算。既定 0）を入れる。評価はシナリオ適用前（板の時点）が既定で、「シナリオ時点のデルタ」に切替可
2. 必要枚数（ミニ）= `round((目標 − 現在のデルタ) × 10)`、必要枚数（ラージ）= `round(目標 − 現在のデルタ)`。両方を提示し、既定はミニ
3. 「追加」で足が入る: 商品 = ミニ先物（既定）、限月 = 直近四半期限月（板の価格がある）、建値 = 板の先物価格、売買 = 枚数の符号。限月は追加後に変えられる（板なしなら手入力）
4. 丸めた後の **残りのデルタ**（例: 「残り −0.03 枚（ラージ）= −0.3 枚（ミニ）」）を表示する。ミニで丸めると残りは ±0.05 以内
5. ヘッジの足は他の足と同じ扱い（削除・編集可）。シナリオで原資産が動くとデルタが変わるので、「再ヘッジ」で枚数を出し直せる（既存のヘッジの足に枚数を足す）

### 5.9 ATM の判定（K7）

ATM は **最新の期近先物の価格から動的に判定**する。JPX ページの ATM 表示（`is_atm`）は使わない（4.4。日中の終値で固定された ATM や、基準の分からない ATM に合わせない）。

| 項目 | 決め |
|---|---|
| 期近先物の価格 `F_fut` | optionchan の `future_price.price`（ラージの直近四半期限月。4.2）。約定時刻 `price_time` をヘッダに出す |
| ATM の定義 | その限月の上場行使価格のうち `\|K − F_fut\|` が最小のもの。**両限月で同じ `F_fut` を使う**（限月ごとのモデル F（5.1）は使わない。オーナー要望） |
| 同距離のとき | 125 円刻みの範囲では先物の呼値（10 円）と行使価格の中点（62.5）が一致しないので起きない。250 円刻みの範囲（中点 125 円）で起きたら、`\|C_mid − P_mid\|` が小さい方（PCP で先物に近い方）。気配が無ければ低い方（put 側） |
| モデル F との関係 | Black-76 の評価は限月ごとの合成先物 F（5.1）、ATM の判定は `F_fut`。両方をヘッダに出す（例: 「先物 67,880 → ATM 67,875 / F(11月限) 67,810」）。差は 2026-10-13 で 70 円（刻み 125 の半分以下）で、ATM が食い違うことはまれ。食い違っても ATM は先物基準のまま |
| シナリオとの関係 | 板の ATM（市場 ATM）はスライダーで動かさない。原資産スライダーの値 `F_fut' = F_fut + ΔF` に最も近い行使価格を **シナリオ ATM** として、損益グラフとスマイルに縦線の印で出す（板の強調は市場 ATM のまま）。テンプレートは既定で市場 ATM を使い、「シナリオの原資産を基準にする」切替でシナリオ ATM を使う |
| 揃えるもの | 板の ATM 行の強調、テンプレートの「ATM」「ATM から n 本外」「1σ 外」（`F_fut × σ_ATM × √T`。σ_ATM は ATM 行の call / put の mid IV の平均）、スマイルの moneyness 軸の基準（表示は `K / F_fut − 1`。補間の内部計算だけモデル F） |
| 鮮度 | 時間外は直前の立会の最後の約定（日中なら 15:45、夜間なら 6:00 の少し前）。寄り前で `price` が NULL のスナップショットは「使える板」の判定（7.2）で飛ばす。先物の `price_time` がスナップショット時刻より 30 分以上古ければ「先物の価格が古い」と表示する |
| `is_atm` の扱い | **使わない**。API の JSON には残す（照合・テストの参考）が、UI には出さない |

### 6.2 主要ユースケース

**U1: 来月限（2 限月）で 1σ 外のストラングル売りを検討**

1. 開く → 最新の板が出る。ヘッダで鮮度と F を確認
2. テンプレート「ストラングル売り」→ 限月 = 2 限月、距離 = 1σ（`F × σ_ATM × √T`）→ 最寄りの行使価格で put 売り・call 売りが 1 枚ずつ入る（建値 = bid）
3. グラフに満期損益と今日の理論損益。指標に BEP・受取プレミアム・最大損失 ∞・デルタ
4. スライダー: 原資産 −8%、IV +5pt、スキュー +2 → 指定日の損益が大きく負になるのを見る（スマイルを無視したツールとの差）
5. sticky moneyness に切り替えて、下落時に put 側の IV が上がる効果を見る
6. URL をコピーして保存

**U2: 翌日のイベント前に 1 限月のプット・デビットスプレッド**

1. 板の 1 限月タブで ATM の put をクリック → 買い（建値 = ask）。500 円下の put をクリック → 売り（建値 = bid）
2. 経過日数 1、原資産 −3% で理論損益を確認。経過日数 0 のまま IV −3pt でイベント後の IV 低下を見る

**U3: カレンダー（1 限月売り / 2 限月買い、同じ行使価格）**

1. テンプレート「カレンダー」→ ATM の行使価格で 1 限月売り・2 限月買い
2. 経過日数を 1 限月の SQ まで進める → 1 限月は満期損益、2 限月は残存 T で理論値（5.5）
3. IV 平行移動で 2 限月のベガの効き方を見る

**U4: 小資金で 1 限月の 30% OTM の put 売り（ファー OTM）**

1. 板の 1 限月タブを OTM 側へスクロール（または「OTM 度 30%」へジャンプ）。bid 28 円 / ask 38 円のような行を見て、IV が「不安定」でない行を選ぶ
2. 行をクリック → 売り（建値 = bid）。指標は円単位（受取 28,000 円 − 手数料）。「最大損失 ∞」の横に −10% / −20% / −30% の損失
3. 損益グラフの横軸を広げて（ピンチ / ホイール）F −45% まで見る。縦軸を手動で ±5 万円にして折れ点と BEP を見る
4. 原資産 −15%、IV +10pt、sticky moneyness で、翼の IV 上昇を含む指定日の損失を見る（ファー OTM 売りの「今の損益」がプレミアムの何倍になるか）
5. 下落のヘッジにミニ先物（乗数 100）の買いを足して、デルタと −20% 時の損失の変化を見る

**U5: ストラングル売りのデルタをミニ先物でヘッジ**

1. U1 のストラングル売り（合計 Δ −0.47 枚ラージ換算 = −4.7 枚ミニ換算）
2. 「ヘッジ」→ 目標 Δ 0 → 「ミニ +5 枚（ラージなら +0 枚、残り −0.47）」→ 追加。足に「ミニ先物 12 月限 買 ×5 @ 67,880」が入り、Δ +0.03 枚（残り +0.3 枚ミニ換算）
3. 原資産 −3% のシナリオで Δ が −0.9 枚に変わるのを見て「再ヘッジ」→ ミニ +9 枚の提案
4. 満期の損益グラフで、12 月限先物の足が 11 月限 OP の SQ 時点で `SQ + basis` で評価されていることを確認（basis を 0 に切り替えて差を見る）

## 7. データ（API とアダプタ）

### 7.1 API

| エンドポイント | 内容 |
|---|---|
| `GET /api/chain` | 「使える」最新スナップショット（7.2）の 2 限月分の板・先物・現物・時刻を 1 つの JSON で返す。約 1,100 行、gzip で数十 KB |
| `GET /api/chain?at=<ISO 時刻>` | `at` 以前で最新の使えるスナップショット（14 日以内）。「直前の引け」と後段の過去時点の検討に使う |
| `GET /healthz` | 設定の読み込みだけ（BigQuery に触れない） |

JSON の形（案）: `{ snapshot_at, delayed_minutes: 15, spot: {price, price_time}, future: {price, price_time, contract_month}, months: [{ last_trading_day, sq_date, strikes: [{ k, call: {bid, ask, bid_iv, ask_iv, price, iv, price_time, delta, gamma, theta, vega, volume, positions}, put: {...} }] }] }`。F の推定・補間・ATM の判定（5.9）はブラウザで行う（サーバーは生の板を返すだけ。計算ロジックを 1 か所にする）。`is_atm` は JSON に残すが UI では使わない。

### 7.2 「使える板」の判定（サーバー）

1. `latest_runs(now − 14 日, now)` で最新 N 件（`rows_option` 付き。数十 KB）
2. `rows_option` が直近 14 日の中央値の 80% 未満のスナップショットは飛ばす（夜間の寄り前の 1/10 の板を除く）
3. 残った最新 1 件の `option_price_latest(t, t + 1 秒)` を読む。ブラウザ側で ATM ±5% の両側気配が 80% 未満なら「寄り前の板」と表示し、「直前の引け」（`?at=` にセッション終了時刻）を勧める

### 7.3 クエリ費用（dry run の実測）

| クエリ | スキャン量 |
|---|---|
| `latest_runs` 14 日 | 約 40 KB |
| `option_price_latest` 1 秒の窓（必要な列だけ） | **約 76 MB**（1 日のパーティション全体を読む。列を全部にすると約 170 MB） |
| `future_price_latest` + `spot_price_latest` 1 秒 | 約 90 KB |

→ `/api/chain` 1 回 ≒ 80 MB ≒ 0.0005 USD（東京のオンデマンド $6.25 / TiB で換算。0.1 円未満）。1 日 50 回で 4 GB、月 120 GB。**月 1 TiB の無料枠内**（ただし無料枠は請求先アカウント単位で他プロジェクトと共有）。optionchan のプロジェクトは **1 日 32 GiB のクエリ量上限**を設定している（runbook「コスト」）ので、**1 日 400 回**を超えると optionchan のビューアーも止まる。対策: サーバーで 60 秒キャッシュ（取り込みが毎分なのでそれ以上の鮮度は無い）、`MAX_BYTES_BILLED` 1 GiB、`at` の範囲を 14 日に限定。

代替案（採らない）: 生 HTML（GCS、1 スナップショット約 48 KB）を直接読んで ingest のパーサーで解析すれば BigQuery 費用ゼロ。ただし生 HTML の封筒形式・パーサーは optionchan の内部で、テーブル関数が公開インターフェース。結合を避けるため BigQuery を使う。

### 7.4 データ元のアダプタ

| 名前 | 用途 | 認証 |
|---|---|---|
| `bigquery` | 本番 / ローカル開発 | Cloud Run は SA、ローカルは ADC（`gcloud auth application-default login`） |
| `file` | GCP を持たない人、オフライン、テスト、固定の板での再現 | 不要。`/api/chain` と同じ JSON を読む。`bigquery` の応答をファイルに落とすコマンドを付ける |
| 手入力 | 板が無くても検討できる | ブラウザ内。API を呼ばない |

### 8.2 推奨: A（開発は C と同じコード）

- データの読み取りに認証が要る以上、**IAP の後ろに置く A がビューアーで実績のある最短経路**。OAuth クライアントも流用できる
- UI と API を **同じオリジン**から出すので、IAP 越しの Cookie / CORS の問題が起きない（ビューアーの API を別オリジンの UI から呼ぶ B' は、IAP の Cookie がオリジンごとで扱いにくい）
- 計算はブラウザなので Cloud Run は板の JSON を返すだけ。費用はほぼ 0
- `file` アダプタと ADC で、A のコードが C（ローカル）をそのまま兼ねる。clone した人は A か C を選べる

B を選ぶ条件: 「インフラを 1 つも増やしたくない」が最優先で、ビューアーに Node のビルドが入ることを受け入れる場合。C を選ぶ条件: スマホ・外出先で使わない場合。

### 8.3 A を選んだときの決めごと

| 決めごと | 推奨 | 理由 |
|---|---|---|
| GCP プロジェクト | **optionchan と同じ** | データセットの読み取りが同じプロジェクト内で済む。IAP の OAuth クライアント（リージョン単位）を流用できる。別プロジェクトにすると、データセットへのクロスプロジェクトの付与と OAuth クライアントの作り直しが要る |
| IaC の置き場所 | **このリポジトリに `infra/bootstrap`（所有者が apply: SA `sa-simulator`、`bigquery.jobUser`、データセットの `dataViewer`（非権威的な `google_bigquery_dataset_iam_member` なので optionchan 側と共存）、IAP のアクセス許可、WIF）と `infra/prod`（CI が apply: Cloud Run、`run.invoker`）** | optionchan-gcp に足すと、このリポジトリの変更のたびに optionchan-gcp の PR が要る。optionchan-gcp 側は何も変えない |
| IAP の OAuth クライアント | ビューアーで設定したリージョン単位の設定を流用。IAP の有効化（`iap_enabled = true`）と `httpsResourceAccessor` はサービス単位 | 追加作業なし。runbook の手順 1・5・6 だけ |
| API の言語 | **Python（Flask / gunicorn）**。ビューアーの `bq.py`（SQL ファイル + クエリパラメータ + `maximum_bytes_billed`）・`settings.py`（環境変数、既定値なし）・テスト（偽 runner）・Dockerfile（uv、非 root、digest 固定）を写す | BigQuery の読み方・セキュリティヘッダ・テストの流儀が揃う。TypeScript（Node）で API を書くと、BigQuery クライアント・テストの流儀を新しく作ることになる。計算は全部ブラウザなので API は薄く、言語の差は小さい |
| 静的ファイルの配信 | Vite のビルド成果物を Flask の `static/` に同梱（Dockerfile の Node ステージ。ビューアーの `vendor` ステージと同じ考え方）。CDN は使わない | CSP `script-src 'self'` のまま |
| 設定 | 環境変数 `GCP_PROJECT`（必須）、`BQ_DATASET`（既定 `optionchan_tokyo`）、`BQ_LOCATION`（既定 `asia-northeast1`）、`MAX_BYTES_BILLED`（既定 1 GiB）、`DATA_SOURCE`（`bigquery` / `file`）、`CHAIN_FILE` | ビューアーと同じ名前 |
| Cloud Run の設定 | ビューアーと同じ: 第 1 世代、CPU 1・512Mi、リクエスト中だけ CPU、0〜2 インスタンス、60 秒、digest 指定 | 実績のある値 |

| セキュリティ | 8.1。入力値は応答・ログに反射しない。BigQuery の例外本文（プロジェクト番号を含みうる）は応答に出さない（ビューアーと同じ） |
| ログ | JSON の構造化ログ（ビューアーの `log.py` と同じ形）。個人情報・資格情報を出さない |
| テスト戦略 | (1) 価格モデル: vitest の単体テスト。既知の値（文献の Black-76 の表）・PCP 恒等式・グリークの有限差分・SQ 損益の折れ点。(2) 補間・F 推定・テンプレート: 固定の板 JSON でスナップショットテスト。(3) API: pytest、偽 runner（ビューアーの流儀）。SQL は `OPTIONCHAN_BQ_TEST=1` のときだけ実テーブルで dry run（スキャン量が 1 GiB 未満）。(4) インフラ: Terraform の静的テスト（IAP 有効、`allUsers` 不在、digest 指定）。(5) E2E は後段（Playwright でユースケース U1）。CI は PR で lint・テスト・docker build・terraform plan、master で deploy（承認付き） |

## 11. プレミアムシミュレーター（MVP の次の段階）

ある原資産価格における理論プレミアムを **行使価格 × IV の表（ヒートマップ）** で見る機能。証券会社のツールにある表に、現在の板との比較を足したもの。優先度は損益シミュレーター（2 章）より下で、MVP の後の最初の段階に置く。同じ SPA の別タブ。

### 11.1 共通化（損益シミュレーターと共有するもの）

| 共有するもの | 内容 |
|---|---|
| 価格モデル（`model/`） | Black-76 の価格・グリーク・IV 逆算、T の数え方（5.2）、限月ごとの F（5.1）、呼値の丸め（3 章） |
| データ（`data/`） | 同じ `/api/chain`（7.1）。新しい API は要らない。`file` / 手入力のアダプタもそのまま |
| UI 部品（`ui/`） | ヘッダ（板の時刻・遅れ・F・限月）、限月の選択、拡大 / パン / リセット（M10）、IV 不安定の印（AC16）、単位（円 / 千円、乗数 1,000 / 100）の切替、板の行の書式 |
| 保存（M8） | 入力の状態を URL / localStorage に保存。損益シミュレーターのポジションから「この足を表で見る」で遷移（行使価格・限月・種別を引き継ぐ） |

### 11.2 入力

| 入力 | 初期値 | 範囲・備考 |
|---|---|---|
| 原資産価格 | 板から推定した限月の F（5.1） | 先物 / 現物 / 手入力に切替。手入力は 1 円刻み |
| 商品 | ラージ OP（当面はこれだけ。K1） | ミニ OP は後段。足すときは乗数 100 と週次限月を 5.7 の仕組みで |
| 限月 / 残存日数 | 1 限月。T は SQ 日 9:00 まで（5.2） | 板の限月に加えて、先の月次限月を一覧から選べる（板なしは理論値のみで、比較列は空）。限月を選ぶと残存日数が入り、日数を直接書き換えてもよい（0.5 日刻み。0 = 満期 = 本源的価値） |
| 評価時刻 | 板の時刻 | 残存日数と連動 |
| IV の範囲と刻み | ATM の IV ±10pt、1pt 刻み | 下限 1%、上限 150%（4.5 の翼に合わせる）。刻み 0.5 / 1 / 5pt |
| 行使価格の範囲と刻み | 板に上場している行使価格そのまま（125 / 250 円の刻み、F −45%〜+33%） | 等間隔（125 / 250 / 500 円）にも切替。範囲は板の最遠まで |
| 種別 | call と put の両方（表を 2 つ、または行を交互） | 片方だけにも |
| 金利 | 設定値（5.6） | |
| 表示 | 価格（呼値で丸め）| 価格（0.01 円）/ デルタ / ガンマ / セータ / ベガ に切替。乗数 1,000 / 100 で 1 枚あたりの金額にも |
| 色 | 対数（1 円〜数千円を同時に見る） | 線形に切替 |

### 11.3 出力

- **表**: 行 = 行使価格、列 = IV、セル = プレミアム。行ヘッダ（行使価格）と列ヘッダ（IV）を固定し、表の本体をスクロール・拡大（M10 の部品）。ヒートマップの色は対数を既定にする
- **板との比較**: 行使価格ごとに板の `bid / ask (板の IV)` を固定列で表の横に出す。各行で **板の IV（mid）に最も近い列を強調**する（= スマイルが表の上で帯として見える）。セルの hover / タップで「その IV の理論価格 − 板の mid」の差と、グリーク（デルタ・ガンマ・セータ・ベガ）を出す
- **逆引き**: 価格を入れると、その行使価格・残存日数での IV を解いて表の対応する列に印を付ける（指値を置くときの IV 換算）
- **ファー OTM・小資金の見え方**: 呼値で丸めた表示では理論価格 1 円未満が「1 円未満」と出る（最小の取引価格は 1 円。0.4 円の理論価格でも 1 円で売買する）。丸めを 0.01 円にすると生の値。1〜5 円の帯は IV 1pt で価格が動かないので、列の刻みを 5pt に粗くできる。セータは 1 日あたり円（乗数込み）で、数円の売りの 1 日の減価が見える

### 11.5 受け入れ基準（AC）

| AC | 検証方法 |
|---|---|
| P1 価格: 表の各セルが `model/` の Black-76 の価格と一致し（0.01 円）、呼値の丸めが仕様どおり（300 円以下 1 円 / 300 円超 5 円。1 円未満は「<1」） | 単体テスト（損益シミュレーターと同じ関数を呼ぶことをテストで固定） |
| P2 初期値: 開くと板から F・ATM の IV・限月・上場行使価格が入り、板の bid / ask / IV が比較列に出る。板が無ければ手入力で動く | 固定の板 JSON でスナップショットテスト |
| P3 範囲: 行使価格を F −45%〜+33%、IV を 1〜150% まで広げても、行・列ヘッダが固定されたままスクロール・拡大で読める（PC・スマホ） | ブラウザで操作 |
| P4 比較: 各行で板の IV（mid）に最も近い列が強調され、hover の「差」が `理論 − 板 mid` と一致する。IV 不安定の行は印が付く | スナップショットテスト |
| P5 性能: 残存日数・原資産の変更で表（100 行 × 30 列 = 3,000 セル）が 16 ms 以内に更新される。300 行 × 150 列でも 100 ms 以内 | 計測（Canvas 描画か DOM の仮想化かは実装時に決める） |
| P6 逆引き: 価格を入れると IV が 1e-6 で解け、表の列に印が付く。価格が本源的価値未満なら「解なし」 | 単体テスト |
| P7 共通化: 損益シミュレーターで組んだ足から「表で見る」で遷移すると、同じ行使価格・限月・残存日数で、損益側の評価価格と表のセルが一致する | スナップショットテスト |
| P8 限月: 限月（板の 1・2 限月と先の月次限月）を選べ、SQ 日と残存日数が表に反映される。板の無い限月では比較列が空になり「板なし（理論値）」と表示される | 固定の板でスナップショットテスト |

### 11.6 実装時に決めるもの

- 表の描画（DOM のテーブル + 仮想化 / Canvas）。拡大 / パンの部品を M10 と共有できる方（Canvas）が有力

- 「板の IV に最も近い列」の定義（mid / bid / ask の切替）

## 12. 後段（MVP の後）

- 日経225ミニオプション（K1）: optionchan にミニのページの取り込みを足す案と合わせて検討。乗数 100・週次限月（金・水曜）

- F の (d) 案（先物 + basis 補正）、営業日ベースの時間

| D11 | 翼の外挿の既定 | 端の傾きを延長（クランプ付き） / 水平 | 傾きの延長（put の翼に追随）。どちらも印を付ける |
| D12 | 板の無い限月（ラージ OP の 3 限月以降）の扱いと優先度 | (a) 手入力のみ / (b) 1・2 限月のスマイルから補間した理論値で代用 / (c) optionchan に 3 限月以降の取り込みを足す（optionchan 側の Issue。ページの有無・形式は要確認） | MVP は (a)。(b) を段階 2。(c) は 3 限月以降を実際に使うなら起票（取り込み行数が増え、optionchan の費用・クエリ量に影響する） |

### 13.3 実装時に決めるもの

- 補間の moneyness 軸（`ln(K/F)` か `ln(K/F) / (σ√T)`）、外挿の扱い（水平 / 端の傾き）
- 「使える板」の閾値（7.2 の 80%）と、寄り前の表示文言
- F 推定の外れ値除去の閾値（5.1）、ペア数の下限（5 組）
- Vite のビルド設定で CSP に合うか（インライン script・`modulepreload` の polyfill）
- キャッシュ TTL（60 秒）と `Cache-Control` の付け方（IAP 越しなので `private`）
- 営業日計算に optionchan の `trading_calendar.toml` を写すか、API が SQ 日を返すか（後者を推奨。カレンダーを 2 か所で持たない）
- 戦略テンプレートの「距離」の定義（σ 倍は `F × σ_ATM × √T`、デルタは補間後の IV で逆算）
- 「IV 不安定」の閾値（ask 5 円以下、IV 幅 5pt）と、翼の外挿のクランプ値（IV の上限・下限）
- 拡大 / パンの実装（uPlot のプラグイン / 自前 Canvas）、横軸の再サンプリングの点数、縦軸の手動スケールの刻み
- 板の「OTM 度 X% へジャンプ」の有無（スクロールだけで足りるか）
