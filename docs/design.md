# option-simulator 設計メモ

日経225オプションの **建てる前の戦略検討** に使う損益シミュレーター（後段でプレミアムシミュレーター）。optionchan（JPX のページから毎分取り込んだ価格・IV を BigQuery に蓄積するツール）の最新の板を初期値に使う。保有管理・発注は対象外。

状態: リファイン 3 回目（2026-10-13。設計レビュー 2 巡目を反映）。0 章の Q1〜Q5 はオーナーが推奨どおりに決定（2026-10-13）。決定済みは 13.1、判断待ちは 13.2、optionchan への依頼は 13.3、変更点は末尾の「変更履歴」。本文中の価格・損益の数値例はすべて **架空の例**（2026-10-13 の板に似せた値を Black-76 で計算したもの）。

リポジトリは誰でも clone して自分の環境で使える汎用の作り（プロジェクト ID・リポジトリ名・メールを埋め込まない。例は `<PROJECT_ID>` 等のプレースホルダ）。

## 1. なぜ作るか（差別化）

| 既存ツールの不満 | この PJ | 根拠・実現手段 |
|---|---|---|
| IV を全行使価格で 1 つにする（スマイル無視）。OTM 売りのリスクが小さく見える | **行使価格ごとの IV** で評価する | optionchan に行使価格ごとの `bid_iv` / `ask_iv` がある（4 章） |
| 行使価格・価格を毎回手で入れる | **最新の板を自動で読み込み**、板・スマイルのクリックで足を追加 | optionchan の最新スナップショット（API 1 回、7 章） |
| シナリオが「今」と「満期」だけ。日数・原資産・IV を同時に動かせない。急落時の IV 上昇を表せない | 経過日数・原資産・IV 水準・スキューの **4 スライダー + 急落プリセット + IV–原資産連動（β）** | 計算はブラウザ内（5 章）。描き直しに通信しない |
| テールの損失が「満期の最大損失 ∞」しか出ない | **テール表**（−5〜−40% × {SQ, 指定日 + シナリオ IV}）を受取プレミアムの倍率つきで | ファー OTM 売りは期中の評価損が問題（5.6） |
| 戦略を並べて比べられない | ピン留め（ゴースト重ね描き）を MVP に、本格比較は後段 | ポジションを URL / ローカルに保存（M8） |
| 操作のたびに再読み込みで重い | 板の読み込み以外は通信ゼロ。描き直し 16 ms 以内 | Canvas 描画（10 章） |
| 夜間は現物が止まっていて評価できない | **先物ベース（Black-76）** なので夜間も評価できる | 夜間は `spot_price` が 15:45 で止まる（4.3） |
| ATM 周辺に固定で **ファー OTM** が見えない・小さい損益が潰れる | グラフ・スマイル・板の **スケールとスクロールを必須**に（M10） | 1 限月の put は 40% OTM まで気配がある（4.4） |
| 行使価格 × IV のプレミアム表が板と切り離されている | **プレミアムシミュレーター**（11 章。MVP の後）。板の bid / ask / IV を横に並べる | モデル・データ・UI 部品を共通化（10 章） |

## 2. スコープ

### 2.1 MVP と縦切り

MVP は 3 つの縦切りで作る。縦切り 1 は GCP 無しで手元で動く。

| 縦切り | 入るもの | 完了の目安 |
|---|---|---|
| **1. 手元で損益が見える** | M9（`file` アダプタ、合成の固定 JSON）→ M1 板 → M2 スマイル → M3 足の追加（OP + 先物、商品・限月・IV の編集）→ M4 損益グラフ（満期 + 指定日）+ M10 スケール / スクロール → M5 シナリオ（4 スライダー + 急落プリセット + β、数値入力・キー操作）→ M6 指標（単位・足別グリーク）+ テール表 → M11 ファー OTM の印 | 固定の板で **U2・U4（手順 4 の証拠金入力を除く）** が通る。AC3〜AC6・AC8・AC10・AC13〜AC18・AC21〜AC24・AC26・AC27 |
| **2. 本番の板で動く** | M9（`bigquery`）、7 章の API・「使える板」判定・キャッシュ、8 章のデプロイ（IAP）、M1 の鮮度表示。作業項目: **JPX グリークの単位の確定**（AC7 の閾値）、Q2 の統計の再測（数日分 + 11 月 SQ 後）、7.2 の夜間の時刻の実測 | 取引時間中・時間外・寄り前で正しい板が出る。AC1・AC2・AC7・AC11・AC12・AC25 |
| **3. 検討を速くする** | M7 テンプレート、M8 保存、M12 デルタヘッジ、M13 ピン留め、M14 証拠金の手入力 | **U1・U3・U5** と U4 の手順 4 が通る。AC9・AC19・AC20・AC28・AC29 |

| # | 機能 | 内容 |
|---|---|---|
| M1 | 板の読み込み | 最新の「使える」スナップショット（2 限月分）。原資産（日経平均・先物）、行使価格ごとの call / put の bid / ask・IV、約定価格・JPX グリーク（あれば）。ATM は 5.9。鮮度（スナップショット時刻・先物の約定時刻・約 15 分遅れ）を常時表示 |
| M2 | スマイルカーブ | 限月ごとに OTM 側（K < F は put、K > F は call）の bid / ask / mid IV を 1 本で描く（5.3）。補間 / 外挿を点線で区別 |
| M3 | ポジションの組み立て | 板（bid タップ = 売り、ask タップ = 買い）・スマイルから足を追加。足ごとに商品（ラージ OP / ラージ先物 / ミニ先物 / マイクロ先物）・限月・売買・枚数・建値・IV（アンカー IV、5.3）を編集可。先物の足は必須、既定はミニ先物（K6）。限月の違う足の組み合わせ可。板の無い限月は手入力（5.7） |
| M4 | 損益グラフ | 横軸 = 基準原資産 X（5.5）。線は最大 3 本: 満期（SQ）、指定日 d、今日（d = 0）。指標計算とグラフ用サンプリングは別（5.6） |
| M5 | シナリオ | スライダー 4 本（経過日数 d、原資産 ΔX、IV 平行移動 Δσ、スキュー Δs）+ **急落プリセット** + **IV–原資産連動** `Δσ_β = −β × ΔX%`（β 設定、既定 1.0pt / 1%）。IV の動き方（sticky strike / moneyness）切替。各スライダーに数値入力欄と刻み（原資産 0.5% or 100 円、IV 0.5pt、日数 1 日。d は小数可）、矢印キー 1 刻み・Shift で 10 刻み、R でリセット、+ / − で拡大。日数の上限 = 最遠の足の SQ。「SQ 日 9:00」「取引最終日 15:45」のボタンで評価時刻をその時刻に置く（整数日のスナップでは T' = 0 に当たらないため） |
| M6 | 指標 | 損益分岐点、最大利益 / 最大損失（解析的。∞ は右側の傾きが負のときだけ）、合計グリーク（単位は 5.6）、足別グリーク、受取 / 支払プレミアム（手数料込み・抜き）、スプレッドコスト（mid − 建値）、建値ずれ（5.3）、**テール表**（原資産 −5 / −10 / −20 / −30 / −40% × {SQ, 指定日 + シナリオ IV}、受取プレミアムの何倍か） |
| M7 | 戦略テンプレート | ストラングル / ストラドル（売り・買い）、バーティカル、アイアンコンドル、バタフライ、カレンダー、レシオ。ATM・ATM から n 本・デルタ・距離（σ 倍・円）で行使価格を選ぶ |
| M8 | 保存 | ポジションとシナリオを localStorage と URL（圧縮 JSON）に。板のスナップショット時刻も残す。最後に取れた板 JSON も localStorage に残し、API が落ちたら「古い板」の印つきで使う |
| M9 | データ元の切替 | `file`（JSON。開発の既定。GCP を持たない人・オフライン・テスト）/ `bigquery`（本番）/ 手入力 |
| M10 | スケールとスクロール（必須） | 損益グラフ・スマイル・板の拡大縮小とパン。横軸の初期範囲は「X と全足の行使価格を含む範囲 + 余白」、拡大の上限は板に出ている最遠の行使価格。縦軸は自動（表示中の横軸範囲に連動。パンで再計算）/ 手動 / 「プレミアム基準（±N 倍）」。ホイール・ピンチ・ドラッグ、ダブルタップ / ボタン / R でリセット。スマイル: 横軸を行使価格 / moneyness / デルタで切替。板: 「ATM へ戻る」固定ボタン、OTM 度 / デルタ / 価格帯（ask ≤ 50 円等）でのジャンプと絞り込み。スマホの板は call / put 切替 + 列を K・bid / ask・IV に絞る。タッチはグラフ内の 1 本指ドラッグ = パン、2 本指 = 拡大、グラフ外はページスクロール |
| M11 | ファー OTM の扱い | IV の分解能の帯（5.3）で「IV 不安定」の印、翼の外挿の明示、指標の単位を円 / 千円で自動切替、ヘッジ枚数が 0 に丸まるときのマイクロ換算の併記 |
| M12 | デルタヘッジ補助 | 合計デルタをラージ先物換算・ミニ先物換算の両方で表示。目標デルタに要るミニ / ラージ先物の枚数を提示し、ワンクリックで足に追加。丸め後の残りを表示（5.8） |
| M13 | ピン留め | 現在のグラフと指標をゴーストとして残し、変更後と重ねる（戦略比較の軽量版。最大 3 本） |
| M14 | 証拠金の手入力 | 証拠金（1 枚あたり円）を手で入れると「建てられる枚数」と「テール損失 / 証拠金」を指標に出す。計算方式の調査は後段（D10） |

### 2.2 受け入れ基準（AC）

| AC | 検証方法 |
|---|---|
| AC1 板: 取引時間中に開くと最新の使えるスナップショットが 3 秒以内に出て、時刻・遅れ・限月（取引最終日と SQ 日）・先物の限月と約定時刻が見える | ブラウザで計測（コールドスタート除く）。API のテストで JSON の形を固定 |
| AC2 板: 寄り前・引け後・時間外は **サーバーが**「板寄せ前の最後のスナップショット」に切り替え、応答の `reason` と画面にその理由を出す。判定の基準は同じスナップショットの `future_price.price` ±5%（7.2） | 16:45〜17:00・15:41〜16:15・土日に確認。判定は単体テスト（固定の `ingest_runs`・板・**先物価格**を入力に、7.2 の規則を固定） |
| AC3 価格: Black-76 の価格が文献値と 0.01 円で一致、価格 → IV → 価格のラウンドトリップが 0.01 円、グリークが有限差分と 1e-4 で一致、極限（T → 0、σ → 0、K → 0 / ∞）で NaN を出さない | 単体テスト（文献値・性質テスト・極限） |
| AC4 IV: 板の OTM 側 ATM ±10% の行は補間なしで IV が決まり、欠損行の補間値に「補間」の印。補間後に K 単調性とバタフライ ≥ 0 が成り立つ | 固定の板でスナップショットテスト + 性質テスト |
| AC5 F: Black-76 から生成した合成の板（price は 1 円に丸め、bid / ask は mid ± 呼値 1〜3）から既知の F* を **±10 円**で回復し、外れ値（1 ペアだけ ±500 円ずらす）を除く。**広いスプレッド（夜間 ATM 150 円 = 30 呼値）のケース**でも ±30 円以内 | 単体テスト |
| AC6 損益: 満期損益の折れ点が **横軸上で `K − basis_i`**（basis 0 の限月は K）に一致し、最大利益 / 最大損失 / BEP が区分線形の解析解（1 円）と一致。put 売りの最大損失は `(K − 受取) × 乗数`（有限。basis > 0 の限月は SQ の下限が basis なので `(K − basis_i − 受取) × 乗数`。5.5）、∞ は右端の傾きが負のときだけ | 単体テスト（各テンプレート、basis ≠ 0 の限月を含む） |
| AC7 指標: JPX グリークのある足だけで、合計デルタ・ベガが JPX 値の合算と整合する。**単位の確定が先**（縦切り 2 の作業項目。確定後に閾値を決める） | 実データの dump（`fixtures/local/`、コミットしない）で手元確認 |
| AC8 性能: 4 スライダーの描き直し 16 ms 以内（横軸 1 画素 1 点、足 10 本） | ブラウザの Performance。CI は計算部分のベンチ |

| AC21 整合: **両側気配があり建値 > 割引本源的価値の足**を板から入れた直後（シナリオ 0、d = 0）の指定日の理論損益が全足で **0 円**（アンカー IV）。スプレッドコストと建値ずれが別に出る | 単体テスト |
| AC22 テール表: −5〜−40% × {SQ, 指定日} の損益と受取プレミアムの倍率が出て、SQ 列は満期損益の式、指定日列はシナリオ IV（β 込み）の Black-76 と一致する | 単体テスト |
| AC23 急落プリセット / β: プリセット「−10% / +20pt / +3」を β = 1 で適用すると、ATM IV は **+30pt**（プリセットの +20pt と β の +10pt は独立に加算）、10% OTM の put は **+33.16pt**（Δs × x_eff / 0.1 で x_eff = ln 0.9 ≒ −0.105 なので +3.16pt が加わる） | 単体テスト |

| AC25 契約: optionchan のテーブル関数 4 本の列・型が、固定したコミットの `schema/tokyo/*.json` と一致し、SQL の dry run が通る | CI（スキーマ照合）、`OPTIONCHAN_BQ_TEST=1` で dry run |

### 4.3 時間と鮮度（時刻はすべてページ時刻 = `snapshot_at`）

- スナップショットは **立会時間中 + 終了後 30 分**だけ。時間外・休業日は新しい行が無い。日中の最後のスナップショットは 15:59、夜間の最初は 17:00
- `snapshot_at` は **ページの更新時刻**で、実時刻より **約 15 分遅い**（21:46 JST 時点の最新が 21:31）。画面にこの時刻と「約 15 分遅れ」を出す
- **行数は時間で変わる**: 日中 1,076〜1,078 行、夜間は 17:01 の 522 行から 20 時ごろ 1,072 行に増える（夜間に上場行使価格が増える。板に出ている最遠は 1 限月 F −67%、2 限月 −82%）。→ 行数の固定閾値は使わない。横軸の上限はスナップショットごと
- **寄り前は板が壊れている**: 夜間の寄り前（16:45〜17:00）は 42 行で価格・IV がすべて NULL、両側気配 10%。17:01 には 522 行で ATM ±5% の両側気配 100%。日中の寄り前（8:39〜8:46）は気配なし 54%・両側 30%
- **引け後は気配が消える**: 15:40 までは 1 限月 ATM ±5% の両側気配 100%、15:41 以降（板寄せ・引け後）は 9〜11%。`quotation`（清算値）は全行にあり、`quotation_date` は **15:46〜47 から当日**になる。夜間の引け（5:56〜6:30）は同様と推定（縦切り 2 で実測）
- 夜間は **現物（日経平均）が 15:45 で止まる**。先物は動く。→ 原資産を現物にすると夜間は評価できない（Black-76 を選ぶ理由）
- JPX の約定 IV・グリーク（`iv`, `delta`〜`vega`）は **約定のあった行にしか無い**（全行の 21〜26%（日中）/ 3〜11%（夜間））。建玉（`positions`）は夜間 17〜20 時は全行 NULL
- 休業日・取り込みの欠落で最新が数日前のこともある。探索範囲は optionchan のビューアーと同じ **14 日**

### 4.4 IV・気配・ATM の実態（結論。表は付録 A）

- **IV の主な出典は `bid_iv` / `ask_iv`**（OTM 側の ATM ±10% でほぼ 100%）。約定 IV はその日の約定があった行だけ（ATM 近辺でも 2〜16%）
- **ITM 側の IV は品質が低い**（`ask_iv − bid_iv` が 5pt 超の行がほぼ全部）。スマイルは限月ごとに **OTM 側だけ**で 1 本作り、ITM の足も同じ `σ(K)` で評価する
- スプレッドは夜間で ATM ±5% が 150〜166 円（IV 換算 1.2〜2.4pt）、5〜10% で 3〜5pt
- 行使価格の刻み: ATM ±10% が **125 円**、その外が 250 円、さらに外は 500〜2,500 円の飛び。同距離の ATM 判定が起きうるのは 500 円刻み以上の領域だけ
- **ファー OTM**: 1 限月の put は 40% OTM まで両側気配が揃い（5〜70 円、IV 42〜117%）、建玉もこの帯に厚い。call の翼は上場自体が薄い（OTM 20% 超は 1 限月 4 本・2 限月 7 本）。2 限月の 40% 超の put は使えない翼（片側・無しが大半）。**呼値 1 円が IV で 1〜3pt に相当**（ask ≤ 20 円）。翼の IV 水準は put で急（10% OTM 31% → 40% OTM 69〜117%）
- **JPX ページの ATM 表示（`is_atm`）**: 日中も夜間も動く（日中の終値で固定されてはいない）。1 取引日分で、**限月ごとの合成先物（5.1）の最寄り行使価格と 78〜82% 一致**、**直近四半期ラージ先物の最寄りとは 1 限月で 32%**（2 限月は先物と同じ限月なので 82%）。= JPX はその限月の理論先物を基準にしていると読める。ATM の基準は 5.9（Q2）
- **JPX の IV は Black-76 + 限月ごとの合成先物 + SQ 日 9:00 と整合**（2 限月 RMSE 0.13pt、1 限月 0.22pt。付録 A.3）
- JPX グリークの単位は未確定（縦切り 2 で確定。AC7）

## 5. 価格モデル

計算はすべてブラウザ（TypeScript、`model/`）。サーバーは板の JSON を返すだけ。

### 5.1 限月ごとの原資産 F（合成先物）

| 案 | 内容 | 判定 |
|---|---|---|
| (a) 先物をそのまま | `future_price.price`（直近四半期限月） | フォールバック。限月がずれる月は 76〜200 円のずれ（4.2）。限月交代で飛ぶ |
| (b) 現物 + キャリー | `S × exp((r − q) T)` | 使わない（夜間は S が止まる。q の推定が要る） |
| **(c) PCP 合成先物** | 下の手順 | **既定** |
| (d) 先物 + 限月差の補正 | (a) に (c) で推定した basis を足す | (c) が決まらないときの代替。後段 |

(c) の手順（限月 i ごと）:

1. ATM ±4% で bid・ask が両側にある行使価格ごとに、無裁定の箱 `[K + (C_bid − P_ask) e^{rT}, K + (C_ask − P_bid) e^{rT}]` を作る
2. 外れ値を除く（箱の幅がその限月の中央値の 3 倍超、または箱が他の箱の交差区間から 300 円超離れるペア）。実データでは合成 F − 先物の全幅が −366〜+870 円に達するペアがあり、除去は必須
3. 残った箱の **交差区間の中点** を `F_i` にする。交差が空なら箱の幅の逆数で重み付けした中央値
4. 不確かさ（交差区間の幅、または重み付き四分位範囲）を画面に出す（例: 「F(11月限) 67,810 ±15」）。ペアが 5 組未満なら (a) にフォールバックして「F = 先物（限月違い）」と表示

### 5.2 時間

- `T = (SQ 日 09:00 JST − 評価時刻) / 365`（暦日）。SQ 日 = 「その月の第 2 金曜。休業日なら前営業日へ繰り上げ」をカレンダー（7.5）で直接求める（`last_trading_day` の翌営業日と一致することをテストで確認）
- 評価時刻の既定はスナップショット時刻。シナリオの経過日数 d（小数可）で `T' = T − d / 365`。「SQ 日 9:00」「取引最終日 15:45」のボタンは評価時刻をその時刻に置く
- **T → 0 の扱い**: `T' ≤ T_min`（= 1 分）なら本源的価値に切り替え、グリークは直前の値で固定、IV 逆算は「解なし」。SQ を過ぎた足は満期損益で、IV の変化は無視する
- 終端は SQ 日 9:00 の一択（3 章）。営業日ベースは後段

### 5.3 IV（アンカー IV・スマイル・補間・欠損）

**足の IV（アンカー IV）**

- 足を入れた時点で、**その足の建値から逆算した IV** を `σ_anchor`、そのときの moneyness を `x₀ = ln(K / F_i)` とする（買いは ask、売りは bid が建値の既定。建値を編集すれば再計算）。足の IV の式は 5.4 の `σ_base` で、**シナリオ 0 では必ず建値に戻る**（AC21）
- `mid − 建値` は「スプレッドコスト」として別に表示する（建値に含めない）
- **アンカー IV が決まらない足**: (i) 建値 ≤ 割引本源的価値（ITM の bid など）→ `σ_anchor = σ_smile(x₀)` とし、`建値 − 理論価格` を「建値ずれ」として別表示。(ii) 片側気配・気配なしの行 → 建値は手入力必須（既定 = ask − 呼値、無ければスマイルの理論価格）、「気配なし」の印。(iii) `T' ≤ T_min` → 本源的価値（5.2）
- ポジション一覧で足ごとの IV を編集できる（AC27）

**スマイル `σ_smile(x)`（限月ごと 1 本）**

- 節点は **OTM 側**の行だけ（K < F は put、K > F は call。4.4）。各節点の IV は mid（両側）→ 片側 → 約定（その立会内）の順
- 「IV の分解能の帯」: 各行で価格 `[p − 0.5, p + 0.5]` 円に対応する IV の幅を IV 逆算で求める。帯が 5pt 超、または ask ≤ 5 円の行は **不安定**として節点から外し、印を付ける（AC16）。不安定行を足にするときもアンカー IV を使い、スマイルは相対シフトにだけ使う
- 横軸 `x = ln(K / F_i)`、縦軸は **総分散 `w = σ² T`** で区分線形に補間（MVP）。補間後に K 単調性（call 価格が K に単調減少、put が単調増加）と **バタフライ ≥ 0** を検査し、違反があれば印を出す。違反とするのは違反量が **関係する行の bid–ask 幅の和の半分**（幅は節点と同じ OTM 側の気配。両側気配が無い行・板に無い行使価格はその行の呼値）を超えるときだけ（呼値で丸めた mid 自体が凸性を数円崩すため。13.4）
- K = F の行の節点: 安定な側だけで平均（片側だけ安定ならその側、両方不安定なら平均して不安定）
- 翼の外挿: `w` を x に対して線形に延ばし、**傾きを 2 以下にクランプ**（Lee のモーメント公式）。加えて端の節点で K 単調性が崩れない傾き（`w' ≤ 2√w Φ(d₂)/φ(d₂)`、左翼は `Φ(−d₂)`）以下にする（Lee の 2 は x → ∞ の漸近条件で、満期の短い限月では端の近くで call 価格が K に増加しうるため）。翼で w が減る向きの傾きは水平にする。水平（端の値）を切替で残す（D11）。外挿値には印
- 後段で SVI 等に差し替えられるよう補間器はインターフェース。限月間の補間は 5.7 (b) のときだけ

### 5.4 シナリオ（IV の 1 本の式）

| スライダー | 意味 | 既定の範囲と刻み |
|---|---|---|
| 経過日数 d | `T' = T − d / 365` | 0〜最遠の足の SQ、1 日（小数可） |
| 原資産 ΔX | 基準原資産 X（5.5）を動かす | **−40%〜+20%**、0.5% or 100 円 |
| IV 平行移動 Δσ | 全行使価格の IV に加える（pt） | **−10〜+40pt**、0.5pt（後段で相対 % 切替） |
| スキュー Δs | **pt / moneyness 10%**。x_eff = ln(K/F) 基準。`Δs = 3` なら 10% OTM の put（ln 0.9 ≒ −0.105）で +3.16pt、40% OTM（ln 0.6 ≒ −0.511）で +15.3pt（call 側は 10% OTM（ln 1.1 ≒ +0.095）で −2.86pt） | −5〜+5、0.5 |

評価に使う IV（足・行使価格 K、限月 i）:

- `x_eff = ln(K / F_eff)`。sticky strike: `F_eff = F_i`、sticky moneyness: `F_eff = F_i'`（シナリオ後の F）
- **足**: `σ_base(x) = σ_anchor + σ_smile(x) − σ_smile(x₀)`（アンカーからの相対シフト）。**足以外**（板の行・テンプレートの候補）: `σ_base = σ_smile`
- `Δσ_total = Δσ + Δσ_β − Δs × x_eff / 0.1`、`Δσ_β = −β × ΔX%`（**IV–原資産連動**。β は設定、既定 1.0pt / 1%。0 で無効）。ΔX% は **評価点の X′ ごと**に `(X′ − X₀) / X₀ × 100` で求める（グラフの横軸の各点・テール表の各列で β が効く。シナリオ点ではスライダーの ΔX と同じ）
- **`σ' = max(σ_min, σ_base(x_eff) + Δσ_total)`**、`σ_min` = 1%。シナリオ 0（ΔX = Δσ = Δs = 0、sticky strike）では `x_eff = x₀` なので `σ' = σ_anchor` → 価格 = 建値

補足:

- **sticky strike**（既定）: 原資産が動いても `σ(K)` は変えない。**sticky moneyness**: スマイルが原資産と一緒に動く。注意: sticky moneyness では **F が下がると固定 K の IV は（put スキューの上で）下がる**。急落時の IV 上昇は β と Δσ で表す
- **急落プリセット**: 例「−10% / Δσ +20pt / Δs +3」「−5% / +8pt / +1」「反発 +5% / −5pt / −1」。3 スライダーを同時に設定するだけ（編集可）。プリセットの Δσ は β と **独立に加算**される（β = 1 のとき −10% のプリセットで ATM は +30pt。AC23）
- SQ を過ぎた足には IV の変化を適用しない

### 5.5 横軸（基準原資産 X）と複数限月

- 横軸は **基準原資産 X**。`X₀` = 1 限月の基準価格 `X₀,1`（5.9。既定は 1 限月の合成先物）。限月ごとの基準価格 `X₀,i`（B なら `F_i`、A なら先物）は moneyness・1σ・ATM に使い、横軸の `X₀` とは区別する
- 足 i の原資産 `F_i`（限月ごとの合成先物、先物の足はその先物価格）について `basis_i = F_i − X₀` を固定し、シナリオと横軸の `X'` に対して **円モード** `F_i' = X' + basis_i`、**% モード** `F_i' = X' × F_i / X₀`（切替。既定は円）
- 満期（SQ）: 足 i の SQ 値は **`SQ_i = X' + basis_i`**（% モードは `X' × F_i / X₀`）として `max(SQ_i − K, 0)` / `max(K − SQ_i, 0)`。横軸上の折れ点は `K − basis_i`（AC6・AC24）。SQ を過ぎた限月の足は満期損益、残る限月の足は Black-76（カレンダー）
- 横軸の下端は全足の原資産が 0 以上になる点 `X' ≥ max(0, max_i(−basis_i))`（% モードは 0）。**固定 basis のモデルでは basis > 0 の限月の SQ の下限は basis になり**、その限月の put 売りの最大損失は `(K − basis_i − 受取) × 乗数`（basis < 0 の限月があると下端は `−basis_i` で、その限月の SQ が 0）
- 先物の足の満期評価は 5.8

### 5.6 損益・指標・グリーク

- 損益 = `Σ 枚数 × 乗数 × (評価価格 − 建値) × 売買符号 − 手数料`。手数料は 1 枚あたり円（既定 0）。受取 / 支払プレミアムは手数料込み・抜きの両方
- **満期損益は区分線形として解析的に**扱う（折れ点 = `K − basis_i`、両端の傾き）。最大利益 / 最大損失 / BEP はそこから 1 円単位で求める。put 売りの最大損失は `(K − 受取) × 乗数`（SQ ≥ 0。basis > 0 の限月は `(K − basis_i − 受取) × 乗数`、5.5）で有限、**∞ は右端（call 側）の傾きが負のときだけ**
- 指定日の理論損益の BEP は符号変化を囲って二分法で 1 円まで。グラフ用のサンプリング（1 画素 1 点）と指標計算は別の関数
- **テール表**（M6）: 原資産 −5 / −10 / −20 / −30 / −40% の各列に {SQ 評価, 指定日 + シナリオ IV（β 込み）} の損益と、受取プレミアムに対する倍率。小資金の売りで効くのは「∞」ではなく、期中の評価損とこの倍率
- 指標の単位: 受け払いの合計が 10 万円未満なら円、以上なら千円（自動。固定も可）。少額の買いは「掛け金 = 支払 + 手数料」と「X 倍になる原資産」
- 金利 r: 設定値（既定 0.5%）。割引 `e^{−rT}` と PCP に使う。T = 1 か月で価格への影響 0.05% 程度（画面の「前提」に桁を書く）

| Γ | X が 100 円動いたときの Δ（ラージ換算）の変化 | |

### 5.8 先物の足とデルタヘッジ

先物の足は必須（K6）。既定は **ミニ先物**。用途は「デルタ 0.5 をヘッジする」ような微調整。

**価格**: 建値の初期値は 5.7。足の価格は 5.5 の `F_i'`（`basis_i` 固定）。損益 = `枚数 × 乗数 × (F_i' − 建値) × 売買符号`。呼値は建値の入力の丸めにだけ使う。

**満期（オプションの SQ）での評価**

| 先物の限月 m とオプションの限月 | 扱い |
|---|---|
| 同じ | SQ 値で最終決済 |
| 先物が後（例: 11 月限 OP + 12 月限先物） | `F = SQ + basis_m`（**basis 固定**が既定。切替で **減衰**: 先物の限月 m の SQ で 0 になるよう線形に減らす） |
| 先物が先（例: 12 月限 OP + ミニ 11 月限先物） | 先に SQ で決済。経路は評価値で平らと仮定し `F = 横軸の値`（単純化。印を付ける） |

**デルタヘッジ補助（M12）**

1. 目標デルタ（ラージ換算。既定 0）。評価はシナリオ適用前が既定、「シナリオ時点」に切替可
2. 必要枚数（ミニ）= `round((目標 − 現在) × 10)`、（ラージ）= `round(目標 − 現在)`。両方を提示、既定はミニ。ミニで 0 枚に丸まるときはマイクロ換算（× 100）を併記
3. 「追加」で足: ミニ先物・直近四半期限月・建値 = 板の先物価格・売買 = 符号。限月は変更可
4. 残りのデルタを表示（ミニなら ±0.05 以内）。「再ヘッジ」で枚数を出し直す

### 5.9 ATM の判定（K7 → Q2 でオーナー再確認）

オーナーの要望は「**最新の期近先物の価格で動的に判定**。日中の終値で固定した ATM は使わない」。実データ（4.4。1 取引日分）では JPX の ATM 表示は固定ではなく動いていて、**限月ごとの合成先物の最寄り**と 78〜82% 一致する。「期近先物」の解釈が 2 つあるので Q2 で決める。どちらでも UI で切り替えられるようにする。

| | (A) 直近四半期のラージ先物 | (B) 限月ごとの合成先物（その月のミニ先物相当） |
|---|---|---|
| 限月 i の基準価格 `X₀,i` | `future_price.price`（例: 12 月限）。両限月で共通 | 5.1 の `F_i`。1 限月・2 限月で別 |
| 動的か | 毎分動く。夜間も動く | 毎分動く。夜間も動く（気配があれば） |
| JPX の ATM 表示との一致 | 1 限月 32%、2 限月 82% | 1 限月 78%、2 限月 82% |
| (A) と (B) の食い違い | 1 限月で **67% のスナップショット**で ATM が違う（差 平均 −76 円、SQ 直後の月は 150〜200 円の見込み）。2 限月（先物と同じ限月）は 12% | |
| 先物の限月交代 | SQ で先物が次の限月に飛び、ATM が飛ぶ | 連続 |
| モデルとの関係 | Black-76 の F と別の値を 2 つ持つ | Black-76 の F と同値（1 つ） |

| ミニ先物で見る「期近」 | ラージの直近四半期限月 | **その月のミニ先物（毎月限月）の価格に相当**。オーナーが主にミニで見ているなら要望に近い可能性が高い |
| 推奨 | | **(B)** |

共通の規則:

- 限月 i の ATM = その限月の上場行使価格のうち `X₀,i` に最も近いもの。同距離（500 円刻み以上の領域でだけ起きる）は `|C_mid − P_mid|` が小さい方、気配が無ければ低い方
- 板の ATM（市場 ATM）はスライダーで動かさない。シナリオ後の `X₀,i' `（5.5 の `F_i'` に相当）に最も近い行使価格を **シナリオ ATM** としてグラフとスマイルに縦線で出す。テンプレートは既定で市場 ATM、切替でシナリオ ATM
- 揃えるもの（**限月ごとの `X₀,i` で**）: 板の ATM 行の強調、テンプレートの「ATM」「ATM から n 本」「1σ 外」（限月 i では `X₀,i × σ_ATM,i × √T_i`。σ_ATM,i は ATM 行の OTM 側 mid IV）、スマイルの moneyness 表示（`K / X₀,i − 1`）。横軸の `X₀` は 5.5
- 鮮度: 基準価格の時刻（先物の `price_time` / 合成に使った板の時刻）をヘッダに。スナップショットより 30 分以上古ければ「古い」と表示。時間外は 7.2 の板で判定
- `is_atm` は **使わない**（JSON には残す。照合・テストの参考）

2. [ヘッジ] → 目標 Δ 0 → 「ミニ +1 枚（ラージ +0 枚、残り +0.02）」→ 追加。足に「ミニ先物 12 月限 買 ×1 @ 67,880」が入り、Δ +0.02 枚
3. 原資産 −5% で Δ が −0.3 枚程度に変わるのを見て [再ヘッジ] → ミニ +3 枚
4. 満期グラフで 12 月限先物の足が 11 月限の SQ で `SQ + basis` で評価されることを確認（**basis 固定 / 減衰** の切替で差を見る）

## 7. データ（API とアダプタ）

### 7.1 API

| エンドポイント | 内容 |
|---|---|
| `GET /api/chain` | 使える最新スナップショット（7.2）の 2 限月分の板・先物・現物・時刻・`reason` を 1 つの JSON で。約 1,100 行、gzip で数十 KB |
| `GET /api/chain?at=<ISO 時刻>` | `at` 以前で最新の使えるスナップショット（14 日以内）。`latest_runs` で `snapshot_at` に解決してから 1 秒の窓で読む。「板寄せ前」「清算値」モードと後段の過去時点に使う。連打は 1 クライアント 10 回 / 分に制限（キーは IAP のユーザー ID ヘッダのハッシュをメモリ内にだけ持つ。保存・ログ出力しない） |
| `GET /healthz` | 設定の読み込みだけ（BigQuery に触れない） |

JSON（案）: `{ snapshot_at, delayed_minutes: 15, reason: "latest" | "pre_open" | "after_close" | "closed", spot: {price, price_time}, future: {price, price_time, contract_month}, months: [{ last_trading_day, sq_date, strikes: [{ k, call: {bid, ask, bid_iv, ask_iv, price, iv, price_time, quotation, delta, gamma, theta, vega, volume, positions, is_atm}, put: {...} }] }] }`。F の推定・補間・ATM の判定はブラウザ（`model/`）。`sq_date` はサーバーがカレンダー（7.5）から入れる。

### 7.2 「使える板」の判定（サーバー。AC2）

時刻はすべて `snapshot_at`（ページ時刻）で書く。基準は **同じスナップショットの `future_price.price` ±5%**（1 限月で約 54 行。サーバーは合成先物を計算しない）。

1. `latest_runs(now − 14 日, now)` を取り、新しい順に見る（約 150 KB）
2. **主判定は気配の充足**: 候補の板を読み、1 限月の先物 ±5% で両側気配のある行が 80% 以上なら採用（`reason = latest`）。行数は補助（`rows_option ≥ 300`。夜間序盤の 522 行を捨てない）。先物価格が NULL（夜間の寄り前）なら不採用
3. 満たさなければ時間帯で分ける: 寄り前（8:39〜8:46、16:45〜17:00）/ 引け後（15:41〜15:59、5:56〜6:30）/ 時間外 → **板寄せ前の最後のスナップショット**（日中 ≤ 15:40、夜間 ≤ 5:55。夜間は縦切り 2 の実測で確定）を返し `reason` を付ける（Q5 の (i)）。候補を読むのは最大 3 回
4. 「清算値」モード（Q5 の (ii)）: `quotation_date` が当日になった 15:46 以降の `quotation` を価格、IV はツール側で逆算。参照列として常に出し、切替で主値にできる

### 7.3 クエリ費用と抑制

| クエリ | スキャン量（dry run 実測） |
|---|---|
| `latest_runs` 14 日 | 約 150 KB |
| `option_price_latest` 1 秒の窓（必要列） | **約 80〜90 MB**。UTC 日パーティション全体を読むので、日中後半 + 夜間 + 翌朝が同じパーティションに入る時間帯は 130〜150 MB |
| `future_price_latest` + `spot_price_latest` 1 秒 | 約 90 KB |

- 1 回 ≒ 100 MB ≒ 0.0006 USD（東京のオンデマンド $6.25 / TiB）。BigQuery の結果キャッシュは立会中（テーブルが毎分更新）は効かない
- 抑制: (1) サーバーのキャッシュキーは **`snapshot_at`**（`latest_runs` だけを引き、変わったときだけ板を取る）。(2) **single-flight**（同時リクエストを 1 本にまとめる）。(3) `MAX_BYTES_BILLED` **512 MiB**。(4) ブラウザは自動ポーリングしない（手動の [最新] だけ）。(5) `?at=` の連打制限。(6) `Cache-Control: private, max-age=60`、`ETag = snapshot_at`
- optionchan のプロジェクトは **1 日 32 GiB のクエリ量上限**（runbook「コスト」）。1 回 150 MB なら 1 日 200 回で上限。手動操作だけなら 1 日 20〜50 回。監視は `INFORMATION_SCHEMA.JOBS` の SA 別集計（D8）
- 後段の候補（費用をさらに下げる）: optionchan の ingest が最新板の JSON を GCS に書く / 最新だけの小さい表を持つ（R4）
- 採らない案: 生 HTML（GCS）を直接解析（optionchan の内部形式に結合する）

### 7.4 データ元のアダプタ

| 名前 | 用途 | 認証 |
|---|---|---|
| `file` | **開発の既定**。GCP を持たない人、オフライン、テスト、固定の板での再現 | 不要。`/api/chain` と同じ JSON |
| `bigquery` | 本番 / 実データでの確認 | Cloud Run は SA、ローカルは ADC（`gcloud auth application-default login`） |
| 手入力 | 板が無くても検討できる | ブラウザ内 |

テスト用の板: **合成データ**（Black-76 から生成した板、または実データから絞って丸めた少数行）をリポジトリに置く。実データの dump は `fixtures/local/`（gitignore）にだけ置き、件数だけ Issue に記録する（JPX 由来のデータを公開リポジトリに置かない。8.1 の D 案を退けた理由と同じ）。dump コマンドは「コミットしない」と表示する。

### 7.5 取引カレンダー

optionchan の `config/trading_calendar.toml`（休業日・立会時間・`covered_until`）が一次情報で、BigQuery には無い。MVP は **シミュレーター側に写し**、CI で upstream（固定したコミット）と比較して差分があれば失敗、`covered_until` の期限切れを検知して警告する。併記: optionchan にカレンダーの公開を依頼する案（R3）。SQ 日の計算は 5.2。

### 8.1 比較

| 観点 | **A. 単独の Cloud Run + IAP** | B. optionchan のビューアーに同居 | C. ローカルのみ | D. 静的ホスティング + 板の書き出し |

| 育てやすさ | 独立して育つ | optionchan-gcp が太る | スマホ・外出先で見られない | 鮮度が書き出し間隔に縛られる |

### 8.2 推奨: A（開発は C と同じコード）

- データの読み取りに認証が要る以上、**IAP の後ろに置く A がビューアーで実績のある最短経路**
- UI と API を **同一オリジン**から出すので IAP の Cookie / CORS の問題が起きない（ビューアーの API を別オリジンから呼ぶ案は IAP の Cookie がオリジンごと）
- 計算はブラウザなので Cloud Run は板の JSON を返すだけ
- B を選ぶ条件: インフラを 1 つも増やしたくない、リリースが optionchan と一体でよい。C を選ぶ条件: スマホ・外出先で使わない

### 8.3 A を選んだときの決めごと

| 決めごと | 推奨 | 理由 |
|---|---|---|
| GCP プロジェクト | optionchan と同じ | データセットの読み取りが同じプロジェクト内。OAuth クライアントを流用できる |
| IaC の置き場所 | このリポジトリ（`infra/bootstrap` を所有者が apply、`infra/prod` を CI が apply）。必要なものの一覧は付録 B | optionchan-gcp 側の変更を不要にする |
| API の言語 | Python（Flask / gunicorn）。ビューアーの `bq.py` / `settings.py` / テスト / Dockerfile を写す | BigQuery の読み方・セキュリティヘッダ・テストの流儀が揃う。API は薄い |
| 静的ファイル | Vite のビルド成果物を Flask の `static/` に同梱（Dockerfile の Node ステージ）。CDN なし。ローカルは Vite の `server.proxy` で `/api` → Flask（同一オリジン維持） | CSP `script-src 'self'` |
| 設定 | `GCP_PROJECT`（必須）、`BQ_DATASET`、`BQ_LOCATION`、`MAX_BYTES_BILLED`（既定 512 MiB）、`DATA_SOURCE`、`CHAIN_FILE` | ビューアーと同じ名前 |
| Cloud Run | ビューアーと同じ（第 1 世代、CPU 1・512Mi、0〜2 インスタンス、60 秒、digest 指定）。検証はリビジョンタグ（トラフィック 0 のタグ付き URL） | 実績のある値 |
| IAP の権限 | `httpsResourceAccessor`（閲覧者）は **bootstrap（所有者 apply、`local.auto.tfvars`）** に置く。付与には `roles/iap.admin` が要り、apply SA には渡さない | optionchan と同じ |

初回デプロイの順序: bootstrap 1 回目（SA・WIF・state・閲覧者は空）→ IAP のサービスエージェント作成 → OAuth クライアントの確認（付録 B）→ prod の apply（CI。サービスと `run.invoker`）→ bootstrap 2 回目（閲覧者を入れる）→ 確認。

## 11. プレミアムシミュレーター（MVP の次の段階）

ある原資産価格における理論プレミアムを **行使価格 × IV の表（ヒートマップ）** で見る。板との比較を足す。同じ SPA の別タブ。優先度は損益シミュレーターより下。

### 11.1 共通化

| 共有するもの | 内容 |
|---|---|
| `model/` | Black-76、T（5.2）、限月ごとの F（5.1）、呼値の丸め、IV の分解能の帯 |
| `data/` | 同じ `/api/chain`。新しい API は要らない |
| `ui/` | ヘッダ、限月の選択、拡大 / パン / リセット、印、単位の切替 |
| 保存 | 入力を URL / localStorage に。損益側の足から「表で見る」で遷移 |

### 11.2 入力

| 入力 | 初期値 | 範囲・備考 |
|---|---|---|
| 原資産価格 | 限月の F（5.1） | 先物 / 現物 / 手入力。現物を選ぶと `F = S e^{(r−q)T}` に換算（q 設定）するか、「現物のまま（換算なし）」の印 |
| 商品 | ラージ OP（K1） | ミニ OP は後段 |
| 限月 / 残存日数 | 1 限月。T は SQ 日 9:00 まで | 板の限月 + 先の月次限月（板なしは理論値のみ）。残存日数は 0.5 日刻み、0 = 本源的価値 |
| IV の範囲と刻み | ATM の IV ±10pt、1pt | 1〜150%。刻み 0.5 / 1 / 5pt |
| 行使価格 | 板の上場行使価格（そのスナップショットの最遠まで） | 等間隔（125 / 250 / 500 円）にも |
| 種別 | call と put | 片方だけにも |
| 表示 | 価格（呼値で丸め） | 0.01 円 / Δ / Γ / Θ / V。乗数 1,000 / 100 |
| 色 | 対数 | 線形に切替 |

### 11.3 出力

- 表（行 = 行使価格、列 = IV、セル = プレミアム）。行・列ヘッダ固定、本体をスクロール・拡大。色は対数
- 板との比較: 行使価格ごとに板の `bid / ask (IV)` を固定列で。各行で板の IV に最も近い列を強調。hover で理論 − 板 mid とグリーク
- 逆引き: 価格 → IV（下限は割引本源的価値。未満なら「解なし」）
- ファー OTM: 呼値で丸めると 1 円未満は「<1」。1〜5 円の帯は列を 5pt 刻みに粗くできる。Θ は円 / 日（乗数込み）

### 11.5 受け入れ基準

| AC | 検証方法 |
|---|---|
| P1 価格: 各セルが `model/` の Black-76 と 0.01 円で一致し、呼値の丸めが仕様どおり（1 円未満は「<1」） | 単体テスト（損益側と同じ関数） |
