# UI / UX ガイドライン

option-simulator の画面が沿う原則と規則、そのよりどころにした世の中のベストプラクティス、画面を触る PR のチェックリスト。

> #326 で作成（2026-10-31）。数値・銘柄の例はすべて架空。

---

## 1. はじめに

**目的**: 画面を足す・直すときに「このアプリではこうする」を 1 か所で引けるようにする。今まで決まりごとは `docs/ui-redesign.md`（§1 の原則・§5 の部品・§10.1 の実装の規約・§11 の決定）、`CLAUDE.md`、Issue の会話に散らばっていた。

**読む人**: 画面を触る開発者、実装・レビューをする AI のエージェント、PR をレビューする人。初めて読む人向けに書く。

**ほかの文書との関係**:

| 文書 | 役割 |
|---|---|
| このガイドライン | **原則と規則**（なぜ・こうする / こうしない・何で確かめるか）。画面の中身が変わっても変わりにくいもの |
| `docs/ui-redesign.md` | **画面の設計の記録**（領域・部品の仕様・決定の経緯・変更履歴）。規則の出どころとして節番号で参照する |
| `docs/user-guide.md` | 利用者向けの操作の説明。画面の呼び名はこちらに合わせる（損益グラフ・シナリオ点の数値・板の情報・インスペクター） |
| `CLAUDE.md` | リポジトリの作りと確認の手順（CSP・色のトークン・文書の書き方） |

食い違ったら、このガイドラインを直すか設計書を直すかを PR で決める（黙ってどちらかに合わせない）。

**このアプリの前提**: 日経225オプションの損益を、建てる前の検討と建てた後の見直しに使う。利用者はトレーダーで、スマホ（360px から）・タブレット・PC のどれでも同じ機能を使う。計算は全部ブラウザで行い、操作のたびに損益グラフと数字が追従する。

## 3. 原則ごとの規則

各行は「こうする / こうしない」とアプリの中の実例。**検査** は機械で確かめているもの（`npm test` の vitest、`npm run ui:check`、`npm run perf`、`api` の pytest）。検査の無い規則は目で確かめる（6 章）。

### P1 一目で読める

- する: `html, body { overflow: hidden }`、画面は `100dvh` のグリッド。スクロールは `.panel-body` の中だけ（設計 §10.1「ページはスクロールしない」）
- する: 常に見せる数字は少なく大きく（スマホ 3 つ = 指定日の損益・満期・Δ、PC 5 つ）。同じ値を 2 か所に出さない（#274 で帯と同じタイルを外した）
- する: 触る頻度で置き場所を決める。毎回触る = 手前、ときどき = 1 タップ、ほぼ触らない = 設定（設計 §1-3・§3 の表）。同じ機能への入口は 1 本（#275）
- しない: 画面の中で状態を文章で説明する（印・色・トーストで示す）
- 実例: 損益グラフが常に見える領域、スマホのシート 3 段階（隠す / 半分 / 全開）、PC の 3 列
- 検査: `ui:check` 既定の実行 = 4 幅 × ダーク / ライト（スマホはシート 3 段階 × パネル）でページの縦・横スクロールが 0px、シナリオ点の数値（`.readout .ro`）が画面内

### P2 物を選んでから操作する

- する: 物（板の行・足の行・タブ・ピン・保存一覧の項目・シナリオ点）を一覧か印で見せ、その物の上に操作を置く。例: 板の行 → bid / ask、足の行 → 枚数 ± / ⇄ / × / 詳細、タブ → メニュー、損益グラフの足マーカー → つかんで行使価格、凡例の ① → ピンの中身
- する: 操作から入る近道（ポジションの「足を追加…」、コマンドパレット、プリセット、AI の [シナリオに適用]、#325 の「板から追加」）は、**物を開くリンク** として作り、開いた先ではいつもどおりの操作にする。特別なモードの操作を増やさない（#325 の決定）
- しない: 同じ物を 2 か所に作る（#325 で「足を追加のダイアログの中に小さな板」を採らなかった理由）
- しない: 先に操作を選ばせてから対象を聞く（動詞 → 名詞）形のウィザード
- 検査: なし（目で。6 章）

### P3 取り消せるなら確認しない

- する: 足の ×・全クリア・タブを閉じる・保存一覧の [上書き]・建値を今の板に合わせる・AI の提案の適用は即実行 + トーストの [元に戻す]（5 秒。設計 §11 決定 8、マニュアル 7 章・11 章）
- する: 戻せない操作（保存一覧の削除・未保存の作業がある [開く]・[空にする…]）だけ、その場の行の中で確認する。画面を覆うダイアログで聞かない。例外は行の無い場面だけ（URL のポジションを開いたときにタブが上限の 6 個なら、ダイアログ「URL のポジションを開く」で [置き換える] / [やめる] を聞く）
- する: [元に戻す] の戻り先は「押す前と同じ位置・名前・足」。戻せないときは理由を文で出す（「戻せなかった（タブが上限）」）
- しない: 「本当に削除しますか？」のダイアログ。`beforeunload` で離脱を止める（自動保存があるので不要。bfcache も壊す）
- 検査: `ui:check --flows` の #84（× / 全クリア → [元に戻す]）・#87 (B)（タブを閉じる → [元に戻す]。切り替えても残る）・#87 (C)（[上書き] → [元に戻す] で保存一覧がバイト単位で同じ）・#135 / #139（AI の適用 → [元に戻す]）

### P4 数字・単位・前提・警告は常に見える

- する: 値・警告・状態は ⓘ に入れず、その場に出す（板の情報の警告のタグ・評価時刻・金額の単位・縦軸の単位・「プレミアム 0 のため自動」。マニュアル 1 章「ⓘ」）
- する: 金額は符号付き（+ / −）、損益の色は `--gain` / `--loss` だが **符号を必ず付ける**（設計 §5.2）。線は色だけでなくラベル（満 / 指 / 今 / ①②③）と線種で区別する（§7.2）
- する: 概算のものは「概算」と書く（証拠金の見出しの副題に 1 回）。古い板・外挿・IV 不安定などの印はタグで値の脇に
- する: 文字のトークン `--ink` / `--ink-2` / `--ink-3` は面に対して両テーマとも 4.5:1 以上
- しない: 単位をヘッダに 1 回だけ書いて値の横に書かない。色だけで正負を伝える
- 検査: `tests/ui/cssTokens.test.ts` (d)（文字 × 面のコントラスト 4.5:1。#279）、`ui:check` の読み取り・タイル・テール表の「切れていない」（値が省略されていない）

### P5 操作はどこでも同じ規則

- する: 十字線は全チャート共通（PC = ホバー、タッチ = タップで置く・交点 ±14px をつかんで動かす・ほかの所のタップで消す。設計 §4.1「十字線の共通の規則」#217）。長押しはチャートごとの既存の意味（損益グラフ = シナリオ点・足マーカー、スマイル = 選択のスクラブ）を守り、十字線に長押しを使わない
- する: ジェスチャーの判定は 1 か所の純関数（`ui/chart/gesture.ts`・`ui/chart/press.ts`）と共用のフック `ui/components/useChartGestures.ts` を通す。チャートごとに `pointerdown` を書かない
- する: Esc = 開いているものを一番上から 1 つ閉じ、フォーカスは開いたボタンへ戻す。ダイアログの中に吹き出しがあれば Esc はそれだけ（設計 §5 ダイアログ）
- する: 同じ役割の部品は同じ部品（`Seg` / `Chip` / `Stepper` / `Menu` / `Popover` / `Dialog` / `Toast`。`ui/next/parts/`）。ステッパーは全部で同じ操作（±・Shift で 10 段・長押し・スクラブ・ホイール・値を押して数値入力）
- しない: 1 つのチャートだけ別の意味のタップ・長押しを足す。メニューの項目を動詞以外にする（1 行 1 動詞）
- 検査: `ui:check --cross`（#217 の十字線の手順を全チャートで）、`--flows` のステッパー（#83）・パレット（#89）・キー（#89 の前半の手順）の手順

### P6 戻るで迷わない

- する: 戻る = Esc。開いているもの（ダイアログ・パレット・説明カード・メニュー・吹き出し・（オーナー決定）スマホのシートの全開）を開くたびに履歴に 1 段積み（URL は変えない）、`popstate` で一番上を 1 つ閉じる。× / Esc / 外のタップで閉じたら履歴の段も取り除く。1 か所のスタック（#320 の設計: `ui/view/backStack.ts` + `ui/next/backStack.ts`）
- する: 説明カードの「関連する用語」は戻り先として 1 つずつ積み、戻る / Esc / [← 戻る] で 1 段、× で全部閉じる。各段の本文のスクロール位置を戻す
- しない: 戻るでアプリの状態（シナリオ・タブ・ピン・拡大・足・テーマ）を巻き戻す。折りたたみ・トースト・十字線・入力中の値を戻るの対象にする。URL に `#settings` のような断片を付ける。「もう一度戻るで終了」の見張り項目を置く。iOS だけの別の仕組みを作る（履歴の仕組みは Safari の左端スワイプでもそのまま効く）
- 実例: 何も開いていないときの戻るはブラウザの既定（アプリを離れる）のまま
- 検査: `ui:check --back`（`--flows` にも入る。#320 第 1 弾）: 390×844・1440×900 で、開く → 戻る 1 回でそれだけ閉じ URL・フォーカスが Esc と同じ / ×・Esc・外のタップ・メニューの項目で閉じた後の戻る 1 回でアプリを離れる（ずれ無し）/ 重なり（保存一覧の中の ⓘ）・置き換え（吹き出し A → B、パレット → 設定）・進む・再読み込み（空振りの回数を出す）・共有 URL の `#p=`・履歴を積まない操作。純関数の規則は vitest（`tests/ui/backStack.test.ts`）。第 2 弾（説明カード）: AI の返答の用語 → 関連の用語 2 つ → 戻る / Esc / [← 戻る] で 1 つずつ戻り、本文の位置・返答の枠の位置・押した用語へのフォーカスが戻る / ⓘ の「用語:」→ 3 つたどる → 戻る 3 回で吹き出しが開いたままフォーカスが「用語:」のボタン / × と箱の外のクリックで全部閉じ吹き出しは残る / 360×780 で本文の位置 / [← 戻る] の見出しの行が折り返さない。用語の列は vitest（`tests/ui/termChain.test.ts`）

### P7 どの幅でも崩れない

- する: 幅の段階は `@media` の 3 段（< 720 / 720〜1199 / ≥ 1200）、パネルの中の詰め方はコンテナクエリ（設計 §10.1「幅の段階」）
- する: 折り返しの規則（設計 §5.1）: 数値・ラベル付きの値・ボタンの文字・セグメント・チップは `white-space: nowrap`。入らないときは (a) 省略記号 (b) 副題を隠す (c) ⋯ へ退避 の順。折り返してよいのは説明文だけ。行に入らなければ横スクロール（チップ行）か列数の変更（板 9 / 7 / 5 列、ステッパー 4 列 / 2 列）
- する: 最も混む状態で測る（タブ 6 個・12 字の名前・警告のタグ・322 行の板・実機相当の字幅）
- しない: 幅ごとに別の画面を作る。スマホだけ機能を落とす（置き場所を変えるだけ）
- 検査: `ui:check` 既定の実行の横スクロール 0px・折り返しの件数（PR で増やさない）、`--parts --max-wraps 0`、切れ（`scrollWidth ≤ clientWidth`）の項目、322 行の板 × 実機相当の字幅、1200 / 1280 / 1800 の市場の列

### P8 指でもキーでも読み上げでも使える

- する: 当たり判定はスマホの記号ボタン 32×32px（アイコン 18px）、折りたたみの行 36px 以上、メニューの項目 36px、チップ 28px、ハンドルの ±14px（設計 §4.1・#82）・十字線の交点の ±14px（設計 §4.1・#217）。記号ボタンの 32px は #292・設計 §2.2。PC・タブレットの記号ボタンは 26px（24px の床は割らない）
- する: フォーカスの輪は `:focus-visible` で、`overflow` で切れる枠は内側に出す。開いたもの（メニュー・吹き出し・ダイアログ・カード）を閉じたらフォーカスを開いたボタンへ戻す。パレット・説明カードの間は背景に `aria-hidden` と Tab の閉じ込め（#124）
- する: 状態は ARIA 属性で表し、CSS もそれを見る（`aria-pressed` / `aria-expanded` / `aria-checked` / `aria-disabled` → `data-*` → 修飾クラス の順。設計 §10.1「CSS」）。アイコンは `aria-hidden`、名前は親の `aria-label` / `title`
- する: トーストは常設の 2 つの読み上げ領域（警告 = `role="alert"`、ほか = `role="status"` + `aria-live="polite"`）に入れる。開閉で作り直さない
- する: キーボードだけで全機能に届く経路（全体のキー 1〜6 / G / T / Ctrl + K、描画域のキー、ステッパーの ↑↓、板の表の PageDown。設計 §4.6）。IME の変換中・修飾キー付きでは奪わない
- する: `prefers-reduced-motion: reduce` で動きの時間を 0 に（トークンだけで書く。P9）
- しない: `section` に `tabindex`（クリックで祖先にフォーカスが移りスクロールが壊れる。#89 R1）。`div` に `onClick` だけ付けてボタンにする。`scrollIntoView`（ページ・`overflow: hidden` の祖先まで動かす。枠の `scrollTop` だけ動かす）
- 検査: `tests/ui/cssTokens.test.ts` (d)、`tests/ui/icon.test.ts`（`aria-hidden`・`currentColor`）、`ui:check` の #292（ボタンの大きさ）・level 1 の見出しが 1 件・`--flows` の #124（`aria-hidden`・Tab が外へ出ない・閉じ方によらず元どおり）・#107（Esc でボタンへ戻る）・#89（キーの行き先）

### P9 速く、動きは因果が追える分だけ

- する: 損益の 3 本 + 指標 + テール表の計算は 16 ms 以内（`npm run perf`。`npm test`・CI は 200 ms = 桁違いの悪化だけ落とす）。開く・切り替える操作の Long Animation Frame は 50 ms を超えないことを目安にする（`ui:check --flows` が件数を数えるが、GPU の無い検査の機械では揺れが大きいので合否には使わない）
- する: 離散の変更（プリセット・枚数 ±・タブ切替・足の追加 / 削除）は線と塗りを 220 ms で補間、連続の変更（ドラッグ・スクラブ・ホイール・連打）は即時（`.live` / `[data-live]`。設計 §6）。時間は `--dur-*` のトークンだけで書き、ms を直書きしない
- する: 重い処理は見せ方で逃がす（面モードはドラッグ中 48×24 の粗い格子、追証マップは止まってから列ごと、ダイアログを `show()` で開く = 322 行の板で `showModal()` が 40〜65 ms かかるため）
- する: 待ちは 250 ms 後にスピナーと文（短い計算でちらつかない）
- しない: 飾りのアニメーション（ホバーの面の変化、浮き沈み）。描画の中で `dispatch` を増やす
- 検査: `npm run perf`（16 ms）、#91 の動きの検査（transition の時間・動きを減らす設定で 0s）。`ui:check --flows` の LoAF の件数は参考（合否に使わない）

### P10 利用者の言葉で、説明は必要なときに引ける

- する: 画面・マニュアル・トーストの言葉は相場の言葉（足・建てる・玉・板・限月・建値・SQ）。呼び名は設計 §2.1 の表に合わせる（損益グラフ・シナリオ点の数値・十字線の値・板の情報・インスペクター）
- する: 開発中の合言葉・内部の識別子（stage・readout・作業台・計器）は画面と利用者向けの文書に出さない（CLAUDE.md「利用者向けの文書の書き方」。設計書の中だけ）
- する: 説明の置き場は近い順に ⓘ（吹き出し。説明だけ、値は入れない）→ 用語の説明カード（ⓘ の末尾・内訳の見出し・AI の返答の用語・パレットの `?`）→ マニュアルの節 → AI（[AI に聞く]）。隠れた操作（ハンドル・数値入力）は最初の 1 回だけ足場の案内を出す（#276）
- する: 記号のボタンは `Icon`（SVG）で、読み上げの名前は言葉（「板を読み直す」）。1 字の省略（満 / 指 / 今）は幅が無いときだけで、全文を `aria-label` / `title` に
- する: 押せない操作は消さずに薄くし、`title` に理由（「タブが上限」）
- しない: 英語の略語を説明なしに新しく作る。トーストの文を毎回違う言い回しにする（固定文 + 数・時刻）
- 検査: `tests/ui/icon.test.ts`（記号の字が残らない）。言葉は目で（6 章）

### P11 安全な作り

- する: CSP は `default-src 'none'; script-src 'self'; style-src 'self'; …`（`api/src/simulator_api/app.py`）。`style` 属性・JSX の `style` prop・HTML 文字列を DOM に入れる API を使わない。位置・大きさが動くものは `data-*` / クラス / SVG の属性 / canvas の 2D API（設計 §10.1「CSP」）
- する: 色は `tokens.css` のテーマの定義の中だけ。足りない色は役割の名前で足す
- する: 保存するものを決める（作業 = `option-simulator.workspace`、端末の設定 = `option-simulator.prefs`）。開いているもの・シートの段階・十字線・AI の会話（sessionStorage）は保存の形式に入れない。形式を変えるときは設計書を先に直す
- する: URL に載せるのは共有のポジション（`#p=`）だけ。利用者の文字を属性の `id` や正規表現に入れない
- しない: 外部のフォント・CDN・画像を読む。ウェブフォントは読み込まない（§7.3）。ギリシャ文字は `@font-face` の `local()`（端末の欧文フォント。`unicode-range: U+0370-03FF`）で描き、`url()` を書かない・フォントのファイルを同梱しない（#324。7 章 5）
- 検査: `api/tests/test_app.py`（セキュリティヘッダ）、`tests/ui/cssTokens.test.ts` (a)(c)(e)（(e) = `@font-face` は `local()` と `unicode-range` だけ。#324）、`.github/scripts/csp-check.sh`（ビルド成果物にフォントのファイル・`url()` の `@font-face` が無い）、`tests/ui/icon.test.ts` (b)（`style` prop が無い）、`.github/scripts/repo-values-check.sh`、`npm run pwa:check`（CSP 違反）

## 7. 決めたこと（2026-10-31・オーナー）

下書きの段階で挙げた論点は、次のとおり決めた（#326）。

1. **置き場と二重化**: `docs/ui-redesign.md` §10.1 の規約はそのまま残す。§10.1 は実装の細部、このガイドラインは原則と規則で、同じことを二重に書かず参照する
2. **当たり判定**: 「スマホの記号ボタン 32px・床 24px（WCAG 2.5.8）」を規則にする（P8）。ⓘ のボタン（18px）はスマホだけ 24px 以上に直す（#327）
3. **[元に戻す] の 5 秒**: そのまま（理由は 4.3）
4. **幅の段階**: 720 / 1200px を Material Design 3 の 600 / 840 に合わせないことを明記する（理由は 4.3 の表）
5. **ギリシャ文字のフォント**: 端末にある欧文のフォントでギリシャ文字（U+0370〜03FF）だけを描く（`unicode-range` で範囲を絞り、`local()` で端末のフォントを使う）。フォントのファイルは同梱しない（P11 の CSP・大きさを保ち、P10 の読みやすさも満たす）。#324
6. **チェックリストの置き場**: `.github/PULL_REQUEST_TEMPLATE.md` に 6 章の「機械で確かめる」8 項目を入れ、「目で確かめる」はこのガイドラインを参照する
7. **足を入れる入口**: 入口は「物を開くリンク」（板から追加 #325）1 本 + 手入力。戦略テンプレート（#20）はポジションの雛形という物として扱い、「同じ機能への入口は 1 本」（#275）と両立させる
8. **文字の拡大（WCAG 1.4.4）**: ブラウザの拡大 200% を PC の 1440px だけ `ui:check` の 1 状態として足す（#328）
