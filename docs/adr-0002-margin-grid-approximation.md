# ADR-0002: 証拠金は格子の最悪値で近似し、JSCC の VaR 証拠金は再現しない

- 状態: 採択
- 日付: 2026-10-19
- 関連: #131・#149・#150・#153・#157、`docs/design.md` 5.10・13.1 K14

## 背景

建てる前に「この形で資金が持つか・どこで追証になるか」を見たい（#131）。日経225オプションの証拠金は JSCC（日本証券クリアリング機構）が決め、2023-11-06 から VaR 方式（指数先物・オプションは HS-VaR。過去 1,250 日の値動きとストレスシナリオで、ポートフォリオの損益の 99% をカバーする額）になった。証券会社はその額に自社の掛目を掛け、ネット・オプション価値（NOV）の扱いを加えて顧客に求める。

JSCC の計算そのものは、証拠金計算ソフトウェア（VMA）と毎営業日のパラメータ（銘柄ごとのシナリオ別損益など）で再現できるが、次の重さがある。

- ダウンロードで利用規約に同意した扱いになる
- 銘柄ごとのシナリオのファイルが 1 日あたり約 110 MB
- ソフトの版が年に 1〜2 回変わる
- 2026-01-26 に足された組合せポジションのストレスシナリオなど、細部が公開資料に無く、自前で作り直しても一致を保証できない

## 決定

- 証拠金は、状態 S のまわりの **固定の格子の最悪の損失** で近似する（原資産 ±R・±R/2・0 × IV の倍率 {1 + u_up, 1, 1 − u_down} × 経過 0 / 2 営業日）。必要証拠金 = `k × PFE`、所要額 = `max(0, k × PFE − NOV)`
- 既定は R 5%・IV ×1.5 / ×0.75・掛け目 k 100%。格子の IV は足ごとの状態 S の IV に倍率を掛け、β は足さない
- 既定は、オーナーの証券会社の額との答え合わせで決めた（同じ日の 6 形: 深い OTM・約 9% OTM・ATM 付近の put の売り、約 10% OTM の call の売り、ストラングルの売り、期先の put の売りで 0.98〜1.07 倍。場中に計算し直した 1 点で 0.96 倍）。この水準は optionchan の 8 年分の日次データの裾（2 営業日の下げの 1% 点 約 −5%、その幅の下げでの IV の倍率の上側）とおおむね合う
- 証券会社の扱いに合わせる設定を持つ: 買いの OP で証拠金を減らさない（既定オン。#149）。証券会社の額は前営業日の清算値で 1 日固定、simulator は今の板で計算する（画面の注記。#164）
- JSCC の VMA・日々のパラメータの取り込みはしない（#153）

## 検討した選択肢

| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. 固定の格子の近似（採択） | 依存・データの取り込みが要らない。ブラウザで 1 状態 約 1 ms。設定で証券会社の額に合わせられる | 近似。相場の水準・ポジションによってずれうる（同じ日の 6 通りのポジションでしか確かめていない） |
| B. 過去 1,250 日の値動きで HS-ES を自前で再現 | JSCC の考え方に近い | 日次の値の取り込みと計算が重い。ストレスシナリオの細部が非公開で一致しない |
| C. JSCC の VMA と日々のパラメータを取り込む | JSCC の額そのもの | 規約への同意・1 日 約 110 MB・版の追従。証券会社の扱い（買いを相殺しない・1 日固定）によるずれは残る |
| D. 証拠金を手入力（旧 M14・#21） | 簡単 | シナリオの点・テール・追証の線で使えない |

## 結果

- 良い点: 建てる前にシナリオの点・テール・追証の線・追証マップ（#152）まで、同じ式で一貫して見られる
- 悪い点: 近似なので、相場が大きく動いた日・特定のポジションでずれが大きくなりうる。答え合わせの記録を #157 で積み、ずれが判断に効く大きさになったら C を別 Issue で検討する
- 残るずれの主因は計算の精度より証券会社の扱い（買いの OP を相殺しない・前営業日の値で 1 日固定）で、これは C を採っても消えない
