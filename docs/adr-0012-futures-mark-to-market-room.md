# ADR-0012: 値洗いをまたいだ状態の余力に先物の評価損益を全部入れる

- 状態: 採択（2026-11-22）
- 日付: 2026-11-22
- 関連: #381、#375（[ADR-0011](adr-0011-margin-room-broker-formula.md)）、`docs/design.md` 5.10・5.11・5.14・13.1 K14

## 背景

- ADR-0011（#375）で、余力の先物の項を `min(0, 生きている先物の評価損益の合計)`（評価益を足さない）にした。評価損益は **建値から** 数えていた
- 証券会社の公開のガイド（会社名は伏せる）では、拘束金額の先物建玉評価損は **前営業日の値洗い価格（当日約定の建玉は建値）と現値の差の当日の合計が負のときの絶対値**。前日までの損益は値洗いで受入証拠金に入る（益も損も）
- そのため、シナリオの指定日 d が日中の引け（値洗い）を 1 回以上またぐと、間の値洗いで益も受入証拠金に入るはずなのに、simulator は益を落とし続け、先物の益が出ている側（先物で OP をヘッジした形の下げ側など）の余力を少なく・追証の線を早く出していた
- オーナーの方向（2026-11-22）: S が建てた時点（今）から引けを 1 回もまたがなければ今の扱い、1 回以上またぐなら最後の値洗いまでの損益は全部受入証拠金に入り、最後の値洗いから S までの分だけ損を引く。ただし simulator はシナリオの途中の経路（最後の値洗いの価格）を持たないので、近似は main に一任

## 検討した選択肢（またいだときの近似）

真の値: 先物の項 = P(建値 → 最後の値洗い c) + min(0, P(c → S))。c の価格が分からない。

1. **最後の値洗いの価格 = S の価格**（採用）: 先物の項 = P(建値 → S)（益も損も）。真の値との差は max(0, P(c → S)) ≥ 0 = 最後の値洗いから S までの益の分だけ余力を多く見る（楽観側）。損の側は一致
2. 最後の値洗いの価格 = 今の価格（すべての動きを最後の立会に置く）: 先物の項 = P(建値 → 今) + min(0, P(今 → S))。建てたばかりの足では #375 の扱いとほぼ同じで、数日〜数週間先の益を全部落とし続ける（この Issue の問題が残る）。保守的だが、保守の根拠が「動きがすべて最後の立会に来る」という起こりにくい経路
3. 今から S までを直線の経路で按分（値洗いの価格を時間で比例配分）: 仮定が増えるだけで当たる根拠がない。損の側も比で削れて、損を少なく見る場面が出る
4. 設定で 1 と 2 を切り替える: 経路を持たないことの説明を利用者に押し付ける。ADR-0011 と同じく、確かめられない扱いのために設定は増やさない

## 決定

1. 値洗い = 営業日の 15:45 JST（日中の立会の終わり。夜間 → 日中で 1 取引日なので 1 取引日に 1 回）。S の時刻 = 板の時刻 t₀ + d とし、`t₀ < c ≤ t₀ + d` の値洗い c があれば「またいだ」（`model/time.ts` の `nextDayClose`・`crossesDayClose`、`model/margin.ts` の `marginMarked`）。t₀ ちょうどの引け（15:45 の板）はその値洗いが建てる前なので数えない。休業日の集合は証拠金の保有期間 h と同じものを使う（祝日取引の日の引けは数えない = 保守側。13.2 D14 は決めない）
2. またいだら先物の項 = 生きている先物の足の評価損益の合計（建値から S まで、益も損も）。またがなければ ADR-0011 のまま `min(0, 合計)`。SQ を過ぎた足の清算額・所要額・NOV は変えない
3. 起点は板の時刻（建てた時点 = 今）。前の板で建てた足（#299）の、建ててから今までの値洗いは数えない（資金の意味づけが要るので別の Issue）
4. 実装は `MarginState.marked`（呼び出し側が `marginMarked` で決めて渡す）→ `MarginResult.futuresMarked` → `marginRoom` の 1 か所。追証の線（`marginCallLevels`）の折れ点の分割は、またがないときだけ（またいだら先物の項は X に 1 次で折れない）。今・シナリオの点・テール・追証の線（`ui/view/margin.ts`）、追証マップのマス（`HoldMapCalc.marked`）、過去の急落の再生（`replayDay`）が同じ判定を使う。売りの効率の線は必要証拠金だけを使うので関わらない

## 理由

- 追証の判定は引けの値洗いの後に行う。追証の線・追証マップ・過去の急落の再生（引けどうしの値）を「S の価格がその日の引けの価格」という **読み方の約束** で読めば、近似 1 は誤差がない（引けの価格 = S の価格）。実装上の S の時刻は板の時刻 + d で、日中の板なら場中の時刻になるので、S を場中の状態として読むときは次の項の誤差がある
- 場中の S での誤差は、最後の値洗いから S までの 1 立会以内の益に限られる。近似 2 の誤差は今から最後の値洗いまでの益の全部で、d が長いほど大きい
- 全項は枚数に 1 次同次のまま（`m·f`）なので、建てられる倍数の式は変わらない
- d に対しては、値洗いの時刻で余力が `max(0, 評価損益)` だけ跳ぶ。値洗いそのものの振る舞いで、説明できる

## 結果

- 先物の益が出ている側で、d が引けをまたいだ状態の余力が今までより大きく、追証の線が遠くなる（先物で OP をヘッジした形のヘッジが効く側で大きい。ADR-0011 で早まった分が、引けをまたいだ日付では戻る）
- 先物の買いの上げ側の追証の線（所要額の増えで出る線）は、引けをまたいだ日付では出にくくなる（益で相殺）
- 今（d = 0）、引けをまたがない日付、OP だけのポジションは変わらない
- 場中の S では、最後の値洗いから S までの益の分だけ余力を実際より多く見うる（楽観側。5.10・マニュアルに注記）
