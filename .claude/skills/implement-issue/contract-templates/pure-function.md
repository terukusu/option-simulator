# 契約テンプレ: 純関数（`model/` の価格モデル・`data/` の正規化など）

対象: 副作用を持たず、同じ入力に対して常に同じ値を返す関数。例: `model/black76.ts` の価格とグリーク、`model/iv.ts` の IV 逆算、`model/forward.ts` の F の推定、`model/smile.ts` の補間・外挿、`model/time.ts` の T の計算、`model/pnl.ts` の損益と指標、`model/scenario.ts` のシナリオ、`data/` の板の正規化。

DOM・通信（`fetch`）・現在時刻（`Date.now()` / `new Date()`）・乱数（`Math.random()`）・`localStorage` が混ざっている関数は、**それらを引数で受ける形に分けてから**、計算部分にこのテンプレを使う（画面部品なら `ui-component.md`）。

## 記入項目

| 項目 | 書き方 | 例 |
|---|---|---|
| シグネチャ | 引数と戻り値の TypeScript の型（`model/types.ts` の型を使う） | `black76Price(type: OptionType, F: number, K: number, T: number, sigma: number, r: number): number` |
| 単位 | 各引数・戻り値の単位を明記する（「数値の約束」と `docs/design.md` 5.6） | 価格は円、T は年、σ は小数（0.25 = 25%。pt ではない）、Θ は円 / 暦日 |
| 定義域 (pre) | 呼び出し側が保証すべき条件と、破られたときの挙動 | `F > 0`、`K > 0`、`T ≥ 0`、`σ ≥ 0` / 範囲外は `NaN` を返さず例外 or 定義した値 |
| 事後条件 (post) | 戻り値が満たす性質を **入力との関係** で書く | `discountedIntrinsic ≤ price ≤ upperBound` |
| 不変条件・性質 | 常に成り立つ性質（性質テストにする） | PCP: `c − p = e^{−rT}(F − K)`、K に対して call は単調減少・凸 |
| 極限 | 境界での値（NaN を出さない） | T → 0 で割引本源的価値、σ → 0 で割引本源的価値、ファー OTM で 0 に近づく |
| 欠損値 | 気配・IV が無い行の扱い | `bid` が `null` なら mid を作らない（0 にしない） |
| 精度 | 許容誤差（`docs/design.md` 9 章「数値精度」） | 価格 0.01 円、IV 1e-6、グリークは有限差分と 1e-4 |
| 性能 | 呼ばれる頻度と予算（描き直し 16 ms の内訳） | 1 画素 1 点 × 足 10 本で 1 回 < x ms |
| 純粋性 | I/O・現在時刻・乱数・グローバル状態を触らない | 評価時刻は引数で受ける |
| 設計との対応 | `docs/design.md` の節と式、AC 番号 | 5.1、AC5 |

## 記入テンプレ

```markdown
### `<関数名>` (`<ファイルパス>`) — 新規 / 改修

- signature: `<型>`
- 単位: <引数・戻り値ごと>
- pre:
  - <条件> (破ったとき: <例外 / 戻り値>)
- post:
  - <入力と戻り値の関係>
- 性質:
  - <PCP / 単調性 / 凸性 / ラウンドトリップ / 対称性 など>
- 極限: <T → 0 / σ → 0 / ファー OTM / K = F での値>
- 欠損値: <null・NaN 入力の扱い>
- 精度: <許容誤差>
- 性能: <予算>
- purity: 副作用なし / 例外: <あれば>
- 設計: docs/design.md <節>、<AC 番号>
- 検証:
  - 文献値: <出典（書名・版・節や数値例）と値>
  - 性質テスト: <種、件数、確かめる性質>
  - 合成板: <生成パラメータと、回復させる値・許容誤差>
- 改修の場合の差分:
  - 現契約 (コードと既存テストから抽出): <現状の挙動>
  - 変更点: <追加 / 緩和 / 強化した条件>
  - 後方互換: 呼び出し元 (grep -rn) と、保存形式・画面の数値が変わるか
```

## 観察可能な AC への落とし方

契約 1 行 → vitest 1 本 → AC 1 行、の対応を保つ。入力は **架空の値か合成の板**（`tests/support/synthChain.ts`）を使い、JPX 由来の実データは使わない。

| 契約 | 観察可能な AC |
|---|---|
| 文献値 | `tests/model/black76.test.ts の「Haug の数値例」が call = put = 1.7011 を 1e-4 で満たす`（出典をテストのコメントに書く） |
| 性質（PCP） | `rng(42) の 400 ケースで |c − p − e^{−rT}(F − K)| < 1e-8` |
| ラウンドトリップ | `価格 → IV → 価格 が 0.01 円以内`（ファー OTM・T 小を含む） |
| 極限 | `T = 0 / σ = 0 / K = 1e9 で NaN を返さない` |
| 合成板からの回復 | `synthChain で F* = <架空の値> の板を作り、推定 F が ±10 円`（外れ値を 1 ペア混ぜても） |
| 欠損値 | `bid が null の行は mid を持たない` |
| 性能 | `npm run perf` が exit 0（16 ms。負荷の低いときに） |

**書いてはいけない AC**: 「正しく計算できる」「妥当な値になる」。テストを通すために許容誤差を緩めるのも不可（緩める必要があるなら理由を設計書と PR に書き、レビューで判断する）。
